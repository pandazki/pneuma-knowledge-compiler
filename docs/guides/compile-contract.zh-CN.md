# 编译契约怎么写

[English](compile-contract.md) | **简体中文**

编译契约是一座文库的宪法。它教编译模型在你的领域里做判断：什么值得被长期记住、记到哪一页、以什么口径记。它是判断力，不是规则清单——这份指南讲的就是这份判断力怎么得出。

契约是一段 markdown 正文，加四个声明字段——`skill_id`、`version`、`path_templates`、`contract_rules`。scaffold 的模板把字段写成正文上方的 frontmatter，正文是编译模型每次任务都会读到的指令：

```markdown
---
skill_id: my-knowledge
version: app-v1
path_templates:
  - people/{slug}.md
  - projects/{slug}.md
  - topics/{slug}.md
---
（记什么、记到什么粒度、用什么口径——即本指南的主题）
```

框架本身不解析这里的任何东西。注册是显式的——`SkillVersion.from_parts(skill_id, version, instructions, path_templates, contract_rules)`——`instructions` 就是 markdown 正文的逐字节原文。frontmatter 是 scaffold 自己的约定（它的驱动器读出字段、剥掉引导注释后再注册）；以编程方式接入的应用直接在代码里声明这些字段。`content_hash` 是这五个部分的 sha256——由 `from_parts` 计算，永不手写——盖进契约产出的每一个正本版本，任何文库状态都能追溯到产生它的那份契约。改契约就是注册一个新 `version`：它塑造将来的编译，永不改写已经记下的内容。可以直接填的骨架在 [`scaffold/templates/contract.zh.md`](../../scaffold/templates/contract.zh.md)，参考契约在 [`packages/pneuma-knowledge-strategies/`](../../packages/pneuma-knowledge-strategies/)，完整的落地示范在 [`examples/opc/`](../../examples/opc/)。

## 1. 核心推理：类型 → 隐含用法 → 入册义务

契约里其余一切都是这一个推理的应用：**现实世界中每种类型的知识，天然暗示它将来会被怎么用；而隐含的用途决定了什么必须被记下来。**

- 反复发生的**事件**，暗示一条**时间线**；
- 在推进的**项目**，暗示一份**持续的进展记录**——目标、决策、里程碑、状态变化；
- 反复出现的**协作者**，暗示一份**不断累积的往来记录**；
- 一个东西**有好几种叫法**（昵称、头衔、缩写、代号），暗示一份**记着别名**的主体页——否则同一主体的故事被名字劈开，检索时再也拼不回来。

两条纪律钉住这个推理：

1. **从材料推，不照抄预设清单。** 上面四条是示范，不是清单。你的领域会暗示它自己的用途；清单会漏，推理不会。用途也随材料演进——数据变了就重推。
2. **用途依赖的事实必须是一等公民。** 检索只能重新浮出被记下来的东西，变不出没人写过的事实。所以「这条用途要靠哪些事实才答得出来」的答案，就是入册义务清单。

动笔前值得知道的两个坑：

- **编译模型偏爱结果，容易丢掉起点。**「什么时候开始的」「谁第一个接手」——这类事实最容易在压缩成结论时蒸发。只要有任何用途要算时长、排先后，就把起点写成显式义务，和终点同等分量。
- **义务成链。** 一次交接同时欠着三条事实：谁交出去、谁接下来、哪一天。推完一条义务，追问一句：要答出它，还缺哪条事实。

契约里写的是推理的**结果**——具体到族的义务（「这一族必须记下 X」）——不是推理过程本身。

## 2. 主体粒度：一个独立演化的东西，一份文档

这是归档的第一原则。一页装所有会把文库压塌：页面无边界地长大、轮转被迫频繁触发、每次检索都命中同一张大页，而「这件事后来怎么变的」再也读不出来——二十个故事交织在同一卷里。

该不该立页，只问一个问题：**它会独立演化吗？** 还会再出现的人、有下一步的项目、会回来的主题——立页。一次性的材料、路过一次的名字——不立，留在 L0，需要时检索得到。

对 `path_templates` 里的每个族回答两件事：**它收什么**（哪些事实归它），以及**新主体什么时候够格开页**（第一次出现就开，还是第二次带着实质信息出现才开）。

**归属错误是最贵的一类错：事实是真的，主体是错的。** 它比漏记更难发现——文库看着什么都不缺，只是挂错了地方；而且编译期分错了页，检索期再聪明也救不回来。所以要按族写清**收什么、不收什么**——尤其是天然互相吸事实的相邻族（人与项目、项目与主题、事件与参与者）。别名记录（§1）是同一种失败在名字维度上的形态：不记别名，一个主体就悄悄变成好几个。

## 3. 什么进正本

对每条候选事实只问一个问题：**它将来会被用到吗——行动、判断、解释、协作、复盘？** 会，入册；不会，原文和索引留着它——L0 直取与词法检索无条件可达，从不依赖契约怎么写——不入册也不丢。正本因此可以把门槛定得很高：它是被判断筛过的少数事实，不是原文的副本。

契约在这一节该写的，是你的领域里**最典型的两三条「值得」与两三条「不值得」**，不是通用清单。个人知识场景的中性基线长这样：值得——明确的决定及其理由、约定与验收条件、带日期的里程碑、反馈的原话、实质性的状态变化；不值得——寒暄、没被采纳的建议、一次性的情绪。你的领域多半不长这样，整段重写。

三个口径是同一判断的延伸，写法始终是**先问用途，再定口径**：

- **证据。** 转述不等于同意，提案不等于决策，「跑通了」不等于「验收了」，「第一次被提到」不等于「开始了」。写清你的领域里谁的话算数、模型和工具的输出算什么、数字要带什么限定。
- **时间。** 相对时间（「下周一」）归一成绝对日期并保留原话；以材料自带的发生日期为准，不确定就标注，不猜。
- **隐私。** 凭证、证件号是框架红线；在此之上写你的领域永远不记什么。

**模态通过证据链进入，不能靠把一切压成文本冒充。** 先确定编译模型及其实际 provider 路由，再选择上下文拼接。路径支持原生媒体时，保持消息顺序、让原始媒体可从稳定的 L0 地址取回，并把图片／音频／文件 content block 绑定到引入它的文字轮次；不支持时，使用明确标成派生表示的 caption、转写或 OCR，注明生成者并继续链接原始媒体。把 URL 渲染成文本不等于送入图片。一个具体例子：OpenAI [GPT-5.6 图片输入全系](https://developers.openai.com/api/docs/guides/images-vision)——Sol、Terra、Luna——都能接收原生图片；按证据所需精度选择 detail，并实测 token 与延迟。经过网关时仍须做端到端能力验证。

契约负责的是这条路径末端的判断：写清某个主体族能否把对原始媒体的直接查看当作证据、派生 caption/OCR 如何归因、需要保留哪些不确定性。契约救不了一条从未把媒体送到模型的上下文管道。

**密度是这一节有没有落地的体检指标。** 一批材料编出的事实条数明显低于常识预期，那很少是克制——多半是某些族的义务没落地，时间线和多跳问题会跟着一起哑掉。

## 4. 机制的归机制：这些不用写

框架已经机械强制了一批规矩：每条 claim 必须带引用、锚点系统分配且不可变、冻结归档卷只读、路径归属、L0/L1 无条件可达（[架构 §5、§9](../architecture.zh-CN.md)）。在契约里重复任何一条都是白花 token——闸门不读散文。

拿不准某条该不该写时，用这条判据：**违反了会被机械拒绝的，是机制，不写；只有人读了文库才能分辨对错的，是判断，才写。**

## 5. 验收环

契约不是想对的，是**用出来的**。一轮的形状：

```
在空库上重建 → 读鸟瞰 → 拿真问题问 → 判断 →
改契约（新 version）→ 重建 → 再看
```

- **在空库上重建。** 契约改动只塑造将来的编译、永不改写已有正本，所以看一次修订最干净的方式是从头建。
- **先读鸟瞰。** 该立的主体立了没有？有没有一页什么都收？有没有一堆只出现过一次的名字各占一页？
- **拿真问题问，带上引用。** 看的不是答得漂不漂亮，而是**答案依赖的事实在不在页上**——答错时先分清病因是「没入册」还是「没取到」，两者的药完全不同。
- **验证归属，不验证字符串出现。**「这个日期在库里某处出现过」是虚假的安心——一年下来几乎每个日期都在某处出现过。事实挂在对的主体上、绑在对的对象上，才算记下了。
- **看结构、写判断。** 「有变化」不是目标，对未来使用更优的建模才是。一次讲得清道理的「不改」也是好答案，同样写下来。并且永远不要凭一两个问题的对错改契约——同一批问题重问一遍，总有一小撮自己翻面；驱动修订的是结构性变化（某类问题整体好转、某个主体的时间线第一次连上），不是单点噪声。

两三轮之后，文库开始看着对了。那就是交付。

「拿真问题问」这一步也有机械化的形态：可选的**覆盖挑战**（见[配置](../reference/configuration.zh-CN.md)）在每次编译后自动跑一轮——依据材料与你的契约盲出题、对照已入册的 claim 判定、确认的缺口经一次过闸门的补偿编译回填。它不取代这个验收环：挑战审计的是入册覆盖，而「建模本身对不对」只有你能判。
