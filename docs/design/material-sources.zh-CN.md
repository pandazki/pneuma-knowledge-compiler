# 材料来源与共享处理器

[English](material-sources.md) | **简体中文**

个人版通过同一种材料 feed 接收本机和其他电脑的编码代理会话。知识库、基础设施与 canonical 写入者仍由
一台宿主机持有。远程采集器只发布观察，不运行第二套知识引擎，也不写 canonical。本设计扩展
[单机个人版](single-machine-edition.zh-CN.md#16-应用负责的增量与常驻同步)的采集边界。

## 1. 应用边界

```
本机日志 ── 共享扫描器/解码器 ── LocalFeed ─────────────────┐
                                                          │
远程日志 ── 同一扫描器/解码器 ── 持久待发送队列 ── R2 ── SnapshotFeed
                                                          │
                         共享 agent-session 处理器 ◀───────┘
                              │ 增量来源合同
                              ▼
                   普通 ingest → L0 + 任务 → 引用闸门
```

**Source** 决定从哪里取得材料，**Processor** 决定一种材料如何变成入库合同。Codex 和 Claude Code
是同一个 `agent-session` 处理器的两种输入解码器。R2 是存储适配器，不是处理器，也不是知识权威。
框架的六种中立来源合同仍是输入边界；材料 feed 位于上游的 `personal/`。

`LocalFeed` 与 `SnapshotFeed` 进入 `personal/skill/scripts/agent_sessions.py` 的同一增量循环。
本机读取保留原始字节前缀检查；远程读取校验规范化快照，不打开发布者的路径。共享循环负责分流、暂存、
分段、续接引用与精确的 `sync-pending` 日志。只有普通 `pkc ingest` 写入 L0。标准合同入库现在把来源行、
原文块、索引和编译任务放在同一个 PostgreSQL 事务中提交。响应丢失后的重试不会留下“来源已存在、
处理任务却未入队”的窗口；历史遗留的孤立导入不会被悄悄重新编译。

## 2. 材料协议 v1

`pneuma.material.agent-session/v1` 是解码器**保留内容**的完整会话快照，不是最终入库合同，包含：

- `schema`、`converter_version`、`material_id`、`snapshot_id`；
- `session`：提供方、原生会话 ID、原项目路径、模型、子代理/冲突标记、保留的发言、最后活动时间与
  确定性的解码计数；
- `origin`：原日志路径、不含凭据的主 git remote，以及设备观察信息。

解码器保留 Owner 发言、代理叙述和受限的行动摘要，不传输原始代理记录、工具正文、推理、注入指令，
也不生成模型总结。材料 ID 标识提供方与原生会话；快照 ID 对规范化会话和解码版本计算哈希。
origin 字段不改变内容身份。传输层另外对上传的精确字节计算摘要，因此同设备、同快照改动 origin
后重传属于冲突。

原路径在宿主机上只是出处标签。缓存路径、容器挂载点、接收端主目录都不替代会话原身份。快照校验检查
协议/版本、摘要、发言 ID、角色/类型组合、时间顺序和行动摘要长度。不支持的版本会被拒绝，不会假装
按新版 v1 解释。

## 3. 持久投递

参考云服务位于 [apps/collector-cloud](../../apps/collector-cloud/README.zh-CN.md)：一个 Worker、
一个属于 Owner 的 SQLite Durable Object，以及 Owner 自己的私有 R2 bucket。两端都只发起向外的
HTTPS 请求，不需要暴露宿主机，也不要求远程采集时宿主机保持开机。

设备先生成并可靠保存随机凭据，再兑换十分钟有效的一次性邀请。兑换是原子的。兑换响应丢失时，可以用
同一设备 ID 和凭据重试，其他竞争者会被拒绝。宿主机凭据不会进入单行邀请、浏览器读响应或设备配置。
云端注册表只保存 API 凭据的哈希，R2 账号凭据不下发给设备。

采集器先把快照的精确字节写入本地待发送队列。云端回执必须与快照、精确摘要、知识库、设备和提交序号
一致，才会删除待发送项。R2 正文与提交清单写完后，注册表才公开序号。尚在写入或失败的对象不会出现在
列表中；重试修复未完成发布，冲突字节不能覆盖不可变对象。序号按提交时刻推进，慢上传不会被快上传的
回执跳过。上传提交前会再次检查设备权限。

采集器发送已排队材料前，会重新检查最新的项目、应用、历史与排除策略。不再获授权的项在本地保留原始
字节，计为暂存且不确认发送；其他已授权项继续上传。恢复授权后，仍用原始字节重试。

宿主机按提交序号分页读取。每个验证通过的版本进入持久处理队列；下载只推进下载游标，处理游标独立
推进。每台设备最新快照在观察后仍保留，暂存会话也能继续判断。多个设备的出处分别保留，处理器对共享
会话历史去重。可证明较旧的副本报告为 stale；同设备历史改写或分叉历史被拒绝。删除云端对象不会删除
已入库的 L0 或 canonical。

设备暂停后保留待发送队列，收到策略后停止扫描。撤销不可逆：云端拒绝后续设备策略读取与上传，采集器
收到拒绝后停止扫描。网络中断时，原本活跃的采集器可以按最后授权范围继续扫描到本地队列。云端不可达
不会阻止本机处理或已下载内容的重放。云端回执代表投递已保存，不代表编译完成。

## 4. 宿主机配置与远程安装

控制台 Home 页提供采集区域。Owner 首次连接已部署的云服务 URL 与宿主机令牌，然后为设备命名，
核对项目、应用与历史范围。结果是一条有时效的命令，也可放在交给目标机 AI 的提示中。界面不假装已用
模型推断范围；目标机 AI 执行安装、检查服务，常驻采集循环由后台进程负责。

安装器校验发布文件，注册用户级 macOS LaunchAgent 或 Linux systemd 服务。使用 Python 3.10+；
缺少时通过 uv 安装托管 Python。采集端不需要 Docker、模型密钥或知识数据库。安装终端里发现的自定义
代理根目录会保存下来供后台使用；自动发现仍使用本机同步相同的 Codex、Claude 与 Orca 规则。

项目范围是 `all` 或**目标电脑上的绝对项目路径**，不隐含包含子目录。`since` 按保留内容的最近活动
时间选择会话，必须带时区；选中的会话保留完整上下文，并不会删除该日期前的发言。范围与排除模式进入
共享扫描器；空或无效范围不会退回 `all`。

`/home/collection/*` 属于个人应用，绑定当前引擎服务的知识库。凭据与配置接口拒绝跨来源及非 loopback
浏览器访问。`collection.json` 权限为 0600，宿主机凭据通过控制台只写不读。本机启停只改
`local_enabled`；旧有各项目的应用、日期和递归监看规则完整保留。替换异构规则是高级配置中的明确动作。
处理器配置变化后，即使材料字节不变，也会重新判断尚未确认入库的增量。

## 5. 稳定项目身份与设备出处

宿主机分配不透明的 `project_id`。**主 origin** 等价的 SSH/HTTPS 写法归为同一个仓库。主机名
规范化，仓库路径保守比较。origin 不同的 fork 保持独立；目录被另一个已知仓库复用时，不会悄悄与之前
的项目合并。没有 remote 的项目按设备及原目录绑定。

应用在证据哈希之外的 `collection-observations.jsonl` 中保存采集观察，关联原生会话、项目 ID、
设备、原路径及入库来源 ID。`collection-projects.json` 是可丢弃的投影，从观察重放；重建不重新分配
已有 ID。观察在 ingest 前写入，避免 worker 比项目归属登记更早开始编译。

应用自己的 `collection-projects` 组件通过框架已有的 `source_preamble` 接口提供机械项目身份行。
`prepare` 读取单租户关联，`rebuild` 重放保留记录，没有 canonical 写入能力。引擎、
`pkchome exec -- pkc` 与知识库受管的 `bin/pkc` 注册相同组件；技能安装和校验也使用这个入口。
每轮临时来源别名不作为持久索引键。这些观察归并来源上下文，不拼接会话、不改写历史 L0，也不绕过引用闸门。

来源页面和引用抽屉通过可选的个人版接口
`GET /home/collection/sources/{source_id}?user_id={user_id}` 将这些关联展示为**采集记录**。
引擎在读取任何记录前拒绝不同租户；只返回与当前来源关联的记录位置，同仓库其他会话不会把各自的设备
带入结果。这些记录证明会话被观察到，不证明某设备是唯一导入端：新观察到的副本可能关联早期增量的来源
ID。时间表示记录生成时间，不是上传时间或设备最后在线时间；没有记录也不代表来自本机。
当前设备名称使用绑定知识库和云地址的可丢弃缓存 `collection-device-labels.json`，只缓存设备 ID 与名称。
云端不可达时仍保留本地关联展示。查看历史版次时省略当前采集记录，避免把现在的归属冒充历史事实。

## 6. 兼容与当前边界

已有本机 watch、来源 ID、成功游标、暂存增量和精确待重试 payload 都可继续使用。验证通过的旧字节
前缀会惰性建立 `sync-materials/` 下的规范化基线引用，会话正文不进入 sync-state。无法验证的历史仍
报告为改写。dry-run 不创建下载缓存、观察或入库状态。

首版参考实现支持代理会话、一个共享可编辑处理器，以及有可用用户服务管理器的 macOS/Linux。
单个规范化快照上限为 8 MiB，超大时明确报告，不截断也不确认上传。设备默认五分钟轮询，宿主机沿用
现有同步计划；通知机制和通用文档/图片采集器是独立扩展。在 Linux 上，退出登录后是否继续运行取决于
账号的 systemd user/linger 配置。宿主机负责入库与编译，休眠会延迟这两步；远程采集和云端保存仍可
继续。知识库仍只有一个权威引擎，这不是多主知识库同步。

## 7. 验证

合成测试覆盖本机/远程合同等价、旧游标迁移、暂存和改写历史、重复/延迟发言、JSONL 半行、分段重试、
多设备出处、独立游标、项目重放与租户拒绝。PostgreSQL 测试在来源、块和任务写入之间注入故障，并竞争
相同导入。云端测试使用真实的本地 SQLite DO/R2，覆盖邀请竞争、权限、冲突上传、部分发布修复、序号顺序
和上传中撤销。原生采集器到云端再到宿主机的集成测试使用合成 Codex/Claude 日志，不使用生产数据，
也不代表已部署到生产云账号。
