## 6. 偏差、事故与防火墙

1. 初次 uv sync 缺 service 依赖 yaml；在冻结前改为 --all-packages，解决，源码未改。
2. 首 session 初次工具输出被截断，后续只重读允许的首 session；未以整条 conversation 排除字段的方式输出。投影先经合成诱饵测试，之后才读真实结构。
3. FREEZE#1 后、执行前发现原始 subprocess 日志潜在泄漏面，改为内存捕获并白名单投影数值/错误类别。保留旧哈希并作修订 A；未根据构建/答题中间结果调参。
4. 官方 README 示例暴露两个答案值，按协议登记烧题；没有读取 questions.jsonl 的金标/证据/category。
5. 首次 detached nohup 没有生成 PID 或状态；记录工具会话回收现象后，改用持续 exec 会话承载 nohup。一次 PID检查因文件不存在报错，无付费构建发生。
6. 两个 compile 历史失败由框架处理，已覆盖；如实计入失败统计，不把成功的外层命令当作全程无 gate 拒绝。
7. 全局 key 用量归属不清触发冻结预算保护。队列中后续库短暂执行了 up/down，付费步骤被 guard 拒绝；没有继续导入。没有为绕过保护改 baseline、换 key、修改脚本或构造空 predictions。
8. 判分未落地，防火墙仍关闭。**未做错题抽样分析**：没有错题判定和合法解锁条件；这项交付标记未完成，不能拿首 session 或推测当错题证据。

## 7. 赌对、赌错与未验证

已被操作证据支持的选择：白名单投影与真实 parser 往返阻止了已知漏文风险；caption 不依赖 image 存在，272 session 均逐字节通过；两栈轮换和逐 session 原子标记完成了118个可恢复单元；自动质询与框架重试正常执行；预算保护阻止了编排继续发起付费工作。

赌错的选择：把可能共享、可能延迟更新的 key 全局计数用于强制预算停止，没有足够细的本实验消费账来判别异常。保守保护发挥了作用，却使全量评测没有走完。仅保留 compile job token 无法覆盖全部角色，且观察文件在 guard 抛错前可能滞后，收尾必须独立重算。这是编排与可观测性失败；现有证据不支持归咎于框架编译质量。

尚未验证：语义切分、people/time、overview、细分契约和全候选结构化答题是否提升回忆准确率；Luna 的质量/价格权衡；时间格式与弃答 doctrine 的考试代价。没有分数就不把这些设计选择称为收益。

后续若重试，应先为实验建立可独立归因的计费边界或完整逐调用账，并对账证明保护只约束本实验；再明确预算、冻结版本和是否复用已构建库。不能重置现有 baseline 后宣称这是原协议无干预续跑。现有状态提供118个完成单元的恢复依据，但原脚本对当前单调增加的 key 用量会继续拒绝付费，直接重启没有意义。
