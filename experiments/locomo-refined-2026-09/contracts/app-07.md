# James and John's evolving personal history

Build a detailed longitudinal record of James, John, and independently evolving subjects. The
permitted first-session sample shows games, programming skills/classes, a dog-walking app idea,
named dogs, an original computer-game project, bowling, arcades, and VR. These are initial signals,
not a closed list.

## Filing model

- `people/`: create James and John immediately. Other people earn a page only when named with a
  durable relationship, role, action, or repeated history. Record each person's work, education,
  skills, preferences, health, values, commitments, relationships, locations, possessions, and
  changes; do not transfer one speaker's fact to the other.
- `companions/`: one page per named animal, tied to the right person, with origin/history,
  traits, health, activities, equipment, and changes. An unnamed pictured animal is not ownership.
- `threads/`: one page per continuing software/game project, class, career path, goal, hobby,
  collaboration, exercise path, travel plan, or other independently evolving effort. Preserve
  beginnings, motives, requirements, participants, steps, setbacks, decisions, and outcomes.
- `events/`: create only for a discrete event with multiple connected facts/stages, participants,
  or later consequences; otherwise use a dated claim on the right person/thread.
- `places/`: create when a visit, move, recurring venue/activity, or plan makes a location useful;
  record who, when, why, what happened, and significance.
- `objects/`: create for a named/repeated possession, notebook, collection, game artifact, vehicle,
  award, artwork, or other object; record ownership, origin, supported appearance, use, and change.

## Recording caliber

Record exact names and titles, programming languages, counts, ages, ranks, dates, durations,
locations, preferences, reasons, requirements, before/after states, meaningful wording, and
explicit negative facts. Preserve attribution. An idea is not an active project, an invitation
is not collaboration completed, and praise is not evidence of success. Keep uncertainty and
contradiction. Omit greetings, generic encouragement, and no-new-fact repeats.

`[caption]` is derived visual description; `[query]` and `[image]` URL are context aids, not proof
alone. Bind an image to a participant/project only when dialogue does so, without invented detail.

## Time, state, and correction

Anchor relative expressions to the session date, retain the phrase, resolve exact days only when
unambiguous, and record beginnings/endings. Jobs, skills under study, residence, ownership,
project/app status, deadlines, scheduled plans, relationships, health/education state, and active
preferences can change. Use `supersede_claim` for changed truth and `edit_claim` for an original
error. Keep future activities future until later confirmed.

## Overview wording

People summaries state current work, skills, commitments, and life threads. Project/event
summaries state current status/outcome and open conditions. Companions, places, and objects define
their connection to the participants. Rewrite only when the current picture changes.
