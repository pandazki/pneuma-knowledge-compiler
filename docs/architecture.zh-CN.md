# 架构

[English](architecture.md) | **简体中文**

整个系统的一页全貌：它承诺什么、数据怎么流、哪些约束被机制强制。`docs/` 下的其余文档都是本页某一节的展开。

## 1. 设计立场

三条承诺定义了这个系统；每一条都由机制强制，而不是靠约定。

**面向领域的知识库建模。** 框架不持有任何领域观点。`load_skill_base` 在部署未注册编译契约时直接抛错，唯一的必填配置（`PNEUMA_KNOWLEDGE_USER_SCHEMA_BASE_VERSION`）就是为了逼出这个声明。记什么、记成什么结构，写在一份你自己的契约里——一个 markdown 文件加一组路径模板；框架只提供领域无关的机器：归一化、索引、检索、校验。

**知识库模型可演进。** 预先定死的建模会随数据量、数据分布和业务本身的变化逐渐失效。所以演进是基础设施而不是事后补丁：编译器在工作中记录事件；框架从这些痕迹里起草 schema 修改并在分支上完成；人评审 diff；一次不经过 LLM 的机械对账合入被采纳的部分（§8）。

**写入层强制溯源。** 编译模型没有整文件写工具，只能一条一条地动知识——追加一条、修正一条，或者记录一条新知识取代了旧那条所说的事实；每条知识必须携带能解析回原文段落的引用。它唯一可以整段替换的区域是一份文档的总览，那段有界，且不得持有它下方账本尚未承载的任何东西。闸门在提交前把这一切机械校验一遍（§5）。编造不是被劝阻的，而是在结构上做不到的。

一条边界：这不是 Agent 记忆系统。Agent 的记忆该记住的是「我**有**一座怎样的知识库」——它怎么建的、大致有什么、怎么查、怎么维护——而不是知识库本身。

三条承诺背后还有一条全程纪律：**机制优先于劝说**。要紧的约束一律实现为写时拒绝、系统分配的身份、确定性的归一化——绝不写成"请模型记得做 X"的提示词。如果你发现自己在写那样的提示词，说明设计错了。

## 2. 系统的形状

```
 raw material ──▶ SourceAdapter ──▶ NormalizedSource ──▶ IntakePlan
                                                            │
              ┌─────────────────────────────────────────────┤
              ▼                                             ▼
        index jobs (L1/L2)                          compile jobs (L3)
              │                                             │
              ▼                                             ▼
   Meilisearch / Qdrant                     canonical library (versioned)
              │                                             │
              ├──────────▶  index components  ◀─────────────┤
              │             derived projections             │
              │             · gate checks · tools           │
              │                     │                       │
              └──────────────┬──────┴───────────────────────┘
                             ▼
            retrieval lanes: rag · fast · deep · briefing · live context
```

**索引组件**（§6）就是图里那个可选的第三个盒子：从同一份 L0 和同一座正本文库派生出来的业务专属结构，由应用贡献，不由框架提供。它读这两样，只写自己的派生投影，再把索引到的东西交给写入闸门、编译模型和检索面。一个都不启用时，这张图就是它一直以来的那两列。

四个包，单向依赖：

- `pneuma-knowledge-core` —— 纯领域逻辑 + 异步 `Protocol` 端口。只依赖 pydantic、langchain-core、langchain、chonkie，**不含任何中间件客户端**。LLM 与向量模型以 langchain-core 类型入参（`BaseChatModel`、鸭子类型的 `Embeddings`）。
- `pneuma-knowledge-service` —— 端口实现：FastAPI 应用、适配器（Postgres、Qdrant、Meilisearch、S3 兼容媒体、Git 子进程）、后台 worker、配置。
- `pneuma-knowledge-strategies` —— 参考编译契约，纯数据包。框架永不 import 它。
- `apps/web` —— 只对 HTTP API 说话的 SPA。

方向是严格的：`service → core`，`web → service API`。core 不 import 中间件客户端，service 不重写领域逻辑。

## 3. 四级访问

每份原始材料逐字保存，并在同一块序列之上保持四层同时可达。这些是并行视图，不是降级链。

| 层 | 内容 | 存储 | 条件 |
|---|---|---|---|
| L0 | 逐字块 + 结构图 + 与块对齐的原始媒体，按 locator 直取 | Postgres + 私有 S3 兼容对象存储 | 无条件 |
| L1 | 块级词法全文检索 | Meilisearch（每用户一索引） | 无条件 |
| L2 | 语义分块 | Qdrant（单 collection，租户过滤在适配器内注入） | 按 IntakePlan |
| L3 | 契约之下编译出的正本知识 | 正本文库（版本化；+ 派生投影） | 按 IntakePlan |

`IntakePlan` 是两个旋钮——`canonical_treatment`（full / distill / card / none）×`semantic_indexing`（full / summary / none）——由材料形状机械提议、可被用户覆写、留有审计。面向用户的摄入原型命名的是**处理意图**而不是体裁——体裁是没有清单能穷尽的开放集合；一个原型就是两个旋钮的一个命名预设。摄入本身廉价且同步：一次导入只写 L0 并入队 `index` 与 `compile` 任务；所有昂贵的事都在 worker 里发生。

## 4. 权威与派生

权威的只有两样：L0 原始材料，和正本文库。正本文库是一部**版本化、只追加的历史**：每次编译追加一个版本，任何历史状态可以打快照、可以回滚，演进在独立分支上接受评审，每个版本都盖着产生它的契约哈希。其余一切——L1/L2 索引、L3 投影、鸟瞰，以及索引组件为自己建的那份索引——都是派生物，可以从这两样完整重建。

（出厂实现：L0 文本、结构与媒体清单存 Postgres，不可变媒体字节存私有 S3 兼容对象存储——本地栈使用 RustFS——并藏在 `MediaStore` 端口之后；正本文库是每用户一个 Git 仓库，commit/tag/revert/branch 恰好一一映射上述语义。它们是适配器，不是架构承诺。）

几条值得内化的推论：

- 即使有 LLM 参与，重建也是字节确定的。语义分块（默认 `semantic` 策略，边界哲学受 [nemori](https://github.com/nemori-ai/nemori) 启发）在同一份结构化 LLM 响应里，为每个主题/episode 返回便于搜索的标题、第三人称事实描述和块坐标。描述保留覆盖块支持的具体参与者、时间、地点、事件、决定、情绪、原因、计划与结果；来源发生日期已知时才换算相对时间，未知时不猜。这份生成内容是派生 L2 内容，不是来源：chunk 文本仍是与机械切块同样寻址的逐字切片。v3 manifest 记录坐标与标题/描述，重建时直接回放。只有边界的旧 manifest 会被一次性补描述，但区间必须逐一与旧记录相等，任何试图改边界的输出都被机械拒绝。超过 `CHUNK_SIZE` 的 episode 会再按句切；scripted/keyless 模型仍回落机械句切。L2 保存两套独立排序的表示：raw 向量只嵌入来源上下文、带标签 caption/OCR 与逐字 chunk；每个 episode 另有一个嵌入来源上下文和标题/描述的向量，并保留这份高密度描述作为派生 payload。每个 point 都解析到对应的逐字 L0 区间。fast recall 可以把高排名描述作为第三种、明确标注的**派生 episode 摘要**上下文，并机械补上来源标题、发生时间、章节和精确块区间；它绝不伪装成逐字原文或 canonical，任何精确细节冲突都以 raw/claim 直接证据为准。检索用普通 RRF 融合词法、raw 向量和 episode 向量，再抑制排名较低的重叠区间；胜出区间不扩宽，重复分数也不累加。因此更好的检索语义既不会稀释 raw 向量，也不会创造第二份权威或引用空间。

  段与段之间还可以*重叠*（`SEMANTIC_OVERLAP`，出厂默认 `smart`）：模型返回前闭后闭的块区间，于是转折句——那句既收束上一话题、又开启下一话题的话——同时被索引进相邻两段；共享多少由模型逐个边界判断，而不是固定步长。它会不会退化，不交给提示词管：五道写入期闸门（端点真实且有序、起点严格递增、无缝隙覆盖、相邻最多共享三块、段数不超过块数）会整份拒收违规输出，该窗口退回零重叠切分。转折块带来的重复完全在派生层——两个 chunk 指向同一批源块（I4），检索侧会抑制排名较低的重叠结果。`off` 保留了原来的零重叠几何形状，但新增 episode 表示已明确建立新的提示词基线；以前只返回边界的测量不会被宣称为这一版的同 harness 结果。
- 升级永不改写正本层。新的投影策略、新的索引、新的渲染、新启用的一个组件——重建的都是派生物；正本历史原地不动。
- 索引组件的投影和其余派生物待在同一侧，两条写路把它钉在那里：框架告诉组件某个来源索引完成（它的增量写），`rebuild_derived` 告诉它整份索引应当从 L0 与正本重新推导。框架里没有任何地方把组件的投影当权威来读，组件也没有通往正本库的写路径——启用一个组件是在文库之上加一层结构，停用它就把这层结构拿走，文库原样如初（I7）。
- 日常提交路径的投影是增量同步：新快照与上一次记录的投影清单做 diff，只有增量落进索引（只对新增或变更的 claim 重算 embedding）。全量重建（`scripts/ops/rebuild_derived.py`）是显式的修复与迁移路径，不是日常路径——无论哪条路，增量都只是成本优化，绝不是新的事实源。

## 5. 正本写入机制

**单位是一条 claim。** 一条 claim 是一段文本，携带**锚点**（嵌在 markdown 里的 HTML 注释 `<!-- c:xxxx -->`）和一条以上**引用**，引用写作 `[cite: <source-id> ¶a-b]`，`¶a-b` 是被引材料里的块区间。锚点内容寻址、系统分配——模型永远不铸造锚点——一经分配不可变。

**一份文档有两部分，只有一部分是账本。** **账本**是正文：带锚点、带引用的 claim，一条一条写入，锚点不可变，没有删除通道。**总览**是账本之上一段有界的头部——文档对其主体的*当前画像*，分四个槽位：`definition`（一句话：这是什么／是谁）、`summary`（现在的状态）、`introduction`（背景、由来、为什么重要）、`connections`（指向其他主体页面的链接，每条一行写清关系）。区域和槽位都由系统写、模型永不键入的 HTML 注释界定（`<!-- overview -->`，每个槽位一个标记），因此读一份文档从不依赖它是被哪个语言包写下的。

**引用语言只有一套，图片也在这套里。** 图片不发明第二套。它附着在消息原有的块上，因此同一个 `source_id + ¶ 块区间` 可以解析出逐字文本、原图字节、摘要、MIME 类型，以及带明确标签和 producer 的 caption/OCR 表示。编译路径按当前编译模型的能力，或只发 caption/OCR，或发真实图片 content block；原生模式在模型调用前重新读取并校验已存字节。caption 始终是派生证据，绝不冒充模型直接看过原图。

**四个写动词，没有第五个。** 编译模型的操作对象是内存中的补丁草稿，每个写工具都被限死在一条 claim 或那段头部上：`create_document` 与 `append_block` 添一条 claim，`edit_claim` 就地修正一条，`supersede_claim` 记录一条新 claim 是旧 claim 所述事实的当前状态，`rewrite_overview` 整体替换那段头部。没有整文档写，所以一条 claim 不可能在誊抄中掉队。读工具——外加启用的组件贡献的那些——补齐整个工具面。

草稿成为 commit 之前必须通过**闸门**：机械检查锚点连续与唯一、引用可解析且形状合法、每条新 claim 有出处、取代链接、总览自己的三道检查、链接目标存在、frontmatter 完整、路径归属于契约模板、冻结归档卷不可写，以及启用的索引组件在自己文档族上追加的那些检查（§6）。引用校验只针对本轮新引入的引用——旧提交里逐字保留的引用被豁免（它们在首次写入时已校验过），所以前向编译永远不会因为一个本轮没给它的来源而被拒；锚点唯一性则相反，全库校验、无豁免。有违规给一轮修复；仍有违规则编译中止，正本层分毫未动。

**每一轮都有自己的一份工具调用预算，而且这份预算是被说出来的，不只是被执行。** 首轮的默认值由材料算出——`max(40, 3 × 本轮来源数)`——因为一轮必须能读完每一个来源、并且每个来源至少追加两次；真实的 88 天重建里，固定的 40 把一个 36 来源的日组截断在追加中途，让 14 个日组（156 个来源）没能进库。部署若声明了 `COMPILE_MAX_TOOL_CALLS`，那就是绝对值。修复轮从不接手首轮剩下的额度：它有自己全新的一份 `max(12, 3 × 违规数)`，以同一个上限封顶——两轮共用一个计数器时，首轮花光就意味着修复轮根本进不了循环，闸门把反馈写给了一个再也不会被问的模型，于是每一次都中止。轮内预算是可见的：剩余降到六次调用这个低水位时，会有一条提示说明还剩几次调用，以及闸门自己的那些判定——本轮改动过的页面欠下的总览、每个启用组件的检查——在当前草稿上已经认定欠了什么，好让最后几次调用花在闸门稍后要的东西上；而被预算截断的那一轮，会在下一轮读到的反馈开头说明这件事，于是修复轮不会把探索从头再来一遍。

**唯一那次整体重写为什么安全。** `rewrite_overview` 一次调用替换整段区域——四个文字槽位，外加旁边那些结构化 `fields`，走 `set_fields` 同一道门整体写入——给它的块铸造全新的系统锚点，账本逐字节不动。总览是一张**快照**，不是变更记录：里面没有任何东西只增不减，写错的那个之所以还修得掉，全靠这一点。每一次调用都是对已经立在那里的那幅画像所作的判断，四种结果就写在调用形状里：保持（不调用）、合并或改写（带上整段新内容调用）、丢弃（槽位全空且不带 fields——区域被删除，文档回到只有断言）。「上一版确实被看过」是机械保证的，不靠嘱咐：`rewrite_overview` 和 `set_fields` 会拒绝本次编译没读过的文档。它安全只有一个理由，而闸门就是这个理由本身，不是一种指望：总览不得持有账本尚未承载的任何东西。每个块都必须引用一条账本 claim（`c:xxxx`）或引用一段来源，可以来自库里任何地方——用一段总览去支撑另一段总览等于什么都没支撑——并且区域有字符上限（`OVERVIEW_BUDGET_CHARS`，默认 2000），使"当前画像"无法长成第二本无人与第一本对齐的账。同一段区域既有上限也有下限：本轮**改动过**的文档，若账本已超过 `OVERVIEW_REQUIRED_AFTER_CLAIMS` 条断言（默认 8）却仍没有 `definition`，就会被拒——先在 `finish_compile` 处拒，再由它身后的闸门拒。原因是模型只会维护已经存在的头部，从不主动开一个（真实库里 85 个页面有 41 个从未有过总览，其中不乏 20–31 条断言的），而一个读不出形状的页面，并不是"知道得还太少"的诚实。本轮没碰过的页面不判：它们在下一次被碰到时收敛。这些规则刻意执行两次：写入工具在写下任何一个字节之前就拒绝该次调用，并一次点名所有不合格的块；闸门留在它身后，作为那些没经过工具就抵达草稿的最终裁判。一条规则若首次是在闸门处听到，代价是整整一轮修复；在工具面听到，代价只是一次调用。`definition` 只有一个短块，因为它就是每一处鸟瞰与提纲要展示的那一行。总览的锚点是锚点连续性唯一的豁免：每次重写都按设计退役，因此丢掉一个不丢任何东西。模型若给一条引用穿上了引用语法的外衣（`[cite: c:xxxx]`），写入边界会把它还原成裸锚点，而不是当违规打回——错的只是那层外壳，剥掉外壳是机制，而为此多跑一轮修复只是一次对话。整次重写只产生一个指名该文档的 `overview_rewritten` 编译事件——而不是新增 N 条、消失 N 条：那在算术上为真，在实质上为假。

**取代把"世界变了"和"我写错了"分开。** `edit_claim` 就地修正一条 claim；`supersede_claim` 记录一条新 claim 是旧 claim 所述事实的**当前状态**——职务、东家、期限。旧 claim 逐字节保留、成为冻结历史；新 claim 紧随其后，带系统分配的锚点和第二个注释指明其前任（`<!-- supersedes: c:xxxx -->`——独立标记，锚点语法不动）。闸门把每条链接约束成同一形状：前任存在、链线性且无环、被取代 claim 的正文不再改动、后继必须引用新证据——"只有新证据才能取代一个状态"是拒绝，不是提醒。仅凭这个标记，框架就派生出文档的**当前视图**（没有后继的 claim）、单个事实的**历史**（它的链），以及一个 `claim_superseded` 编译事件——简报把它叙述为状态变化而非新增。按*日期*走一条链——某一天成立的是哪一条——需要一本日历，正本没有日历；那是 `time` 组件的 `as_of`（§6）。两个动词都保留块的*形态*：以列表项存在的 claim 改完仍是列表项，无论替换文本以什么形式送来——块的形状是文档的结构，不是这次写入所关心的措辞。

**轮转是维护，不是判断。** 超过尺寸阈值的文档会轮转：较老的 claim 逐字节搬入冻结的归档卷（`<doc>/aNN.md`），活动文档保留近期尾部和一张机器托管的历史卡片，专用闸门断言搬运前后字节守恒、锚点精确存活。卡片不是总览：卡片索引归档，总览解读账本，轮转过的文档两样都有。

可选的**覆盖挑战**（默认关闭）在每次编译落地后立即审计：出题是盲的——只依据材料与契约、绝不看编译结果——拿题探针已入册的 claim，以材料为真值判定缺口。确认的缺口送入一次补偿编译，其写入与任何编译一样过闸门；审计只负责指出，强制仍归闸门。

## 6. 编译契约（skill）

契约以 `SkillVersion` 注册：skill id、版本、instructions（判断力——什么值得记、记到什么粒度、用什么口径）、路径模板（文库的目录骨架，也是写权限的唯一依据）、契约规则。整体做哈希，哈希盖进每个正本 commit——任何一个文库状态都能追溯到产生它的那份契约原文。

框架只在两个方向上扩展，而这两个方向扩展的东西不同。

**schema pack 扩展的是判断力。** 它们是追加式的契约片段，按用户确定性地叠加在基础契约之上——pack 只能加文档族，不能减。pack 是文本，它改变的是什么值得被记下，并与它所扩展的契约一起进同一个哈希。

**索引组件扩展的是结构。** 组件是叠加在某个契约 family 之上的业务*结构*，通过一个协议（`components/`）接入框架自己的那些缝：闸门的写入时检查——每一条写正本的通道都要跑它，每日编译、全库 evolve、以及把一次重组落地的 adopt 合并都一样，因为字段不变式属于正本，而不属于某一个写入者——编译 outline 里该族文档下的附加一行、给编译模型的读工具、给深召回的工具、给快召回的路由查询路（§7）、编译任务里某个来源下的一行机械说明——写出源边界知道、而转录看不出的事实——以及一条**投影通道**：框架会告诉组件某个来源已完成索引，并在显式的 `rebuild_derived` 时告诉它整份索引该重新推导。于是组件可以持有自己的持久化投影，和其余派生层一样是派生的、可重建的（I2、I7），并且 fail-soft：组件抛错最多让投影变陈旧，绝不会让作业失败。core 不认识任何组件；和契约一样，由应用注册它启用的那些（`PNEUMA_KNOWLEDGE_COMPONENTS`），不认识的名字在启动时大声报错，一个都不注册时每个缝的渲染与这个概念出现之前逐字节相同。启用的组件集合会和契约哈希、overlay 哈希一起盖进每个正本 commit 的 trailer，于是一个 commit 说得出：哪份契约、哪套措辞、哪些组件产生了它。

组件不能越过的那条线，正是这道缝安全的原因：**它持有结构和指针——身份、边、计数、区间，每一项都解析到一个来源区间或一个 claim 锚点——从不持有散文知识。** 它索引，它不"知道"。它推导出的东西直接服务于检索；要进正本只有一条路，就是搭一次普通编译的车：契约裁定它摆到面前的东西，同一道闸门审判结果。没有升格步骤，没有第二个评审模型，也没有第二份权威。

随包附带两个参考实现。**`people`** 给人物页两个机器可读的 frontmatter 字段——`identities`（`scheme:value`，一个身份至多绑一页）与 `aliases`（不能是别人的名字：既不能是另一个人物页的别名、标题或 slug，也不能是来源为某个不在本页上的身份记下的显示名）——两者都属于总览、随它整体写入；两条都是事实，闸门与写入面机械地拒绝，还有第三条：**在同一场对话里都发过言的两个「人的 id」是两个人**，一个页面不能同时绑住它们（IM 的 `sender_id`、会议的 `speaker_id` 是「人的 id」；邮箱地址不是——一个人用两个地址写信再寻常不过，而 `email/v1` 不确立它们之间的任何同一性）。这几条都只针对本轮**动过**的页面判定——正文或 frontmatter 与本轮开头不同，或页面是新建的——于是一个旧的错页不会挡住之后每一次编译，而动过它的写入也一次都逃不掉；完整的规则集合是 `people.identity_shape`、`people.identity_duplicate`、`people.identity_cospeakers`、`people.alias_collision`、`people.alias_undecided` 与 `people.not_ready`，最后一条在全库镜像加载失败时拒绝这一轮，而不是拿一座空文库去判它。此外还给编译器一个 `find_person` 查询，一条 `person` 快路，一条 `people_around(subject)` 快路及其深召回工具——文库与某个项目、团队或话题相连的那些人，从正本自己的链接派生，并把写下这条关系的 claim 当作证据，专答那种只点了主题、没点任何人名的问题——以及 `enumerate_identities`：来源在某个日期范围内记录到的全部外部身份的闭合集合，每一项标明绑定到的人物页或 `(unbound)`，于是"所有和……的人"这类问题是对一份完整候选表逐个判断、残差可见，而不是对检索命中作答。它还持有一份**称呼词**的持久化投影，从轮次结构里读出，由集中度而不是频次裁定。又因为闸门不逼的证据就是模型会跳过的证据，凡是本次编译的来源里出现的人，全库为他报出的每一个称呼词，都必须在本轮结束前要么被记进该页的 `aliases`，要么被否掉（`decline_alias`）——而这个问题**只问一次**。一次否掉哪里都不存：正本记的是关于一个人已知的事，不是那些不属于他的名字。把问题关掉的是这一页被写下，判据是文库本来就握着的两个派生日期——投影里的 `reported_since`（这一对越过报出门槛的那一天）对上正本最后一次提交这一页的日子——于是之后被写过的页面就是被摆到过这个问题面前的页面，从此不再问，不管它当时怎么决定。框架让这个决定无法回避，至于决定本身是什么，完全交给契约。**`time`** 为每个 L0 块保留一行派生数据——该块的 UTC 瞬间，以及它落在知识主体时区里的哪一个日历日，连同那个时区本身和它的来处——并提供一条 `timespan` 快路、`timeline` / `as_of` 一对深召回工具，以及编译任务里每个来源的时间行。两者的完整说明，连同写第三个组件的清单，见 [design/index-components.zh-CN.md](design/index-components.zh-CN.md)。

框架里所有模型可见的文案都住在一个 **prompt 目录**里，可在启动时整体覆盖；覆盖集同样做哈希、与 skill 哈希并排落盘，让每个部署有一个两轴身份：*哪份契约，哪套措辞*。渲染出的 system message 字节稳定：没有时间戳、没有任务内容——那些走 human message。这既让 provider 的 prompt 缓存真正生效，也让编译行为可归因。

契约本身怎么写是一门手艺，见 [guides/compile-contract.md](guides/compile-contract.md)。

## 7. 检索

同一座文库上四条检索面，成本递增：

- **rag** —— L1 与 L2 并行、倒数排名融合；返回命中列表，不动用 LLM。
- **fast** —— 对组装好的上下文做一次 LLM 调用：文库鸟瞰、L3 claim、派生 L2 episode 摘要和 L1/L2 逐字窗口。

鸟瞰会带上每份文档标题下一层的信息：它的总览 `definition`，和编译提纲展示的是同一行，因此判断该读什么的检索面无需打开任何一份，就能把两个名字相近的页面分开。没有 definition 的页面，这一行退回它自己当前的账本，标签用 `ledger:` 而非 `definition:`——一页承载得少时，那几条断言本身就是它的总览；这里不生成任何东西（用断言自己的原话，去掉机制标记、markdown 与被取代的旧状态——markdown 到展示文本走同一个转换：链接留下文字、丢掉路径），按 definition 同一上限**在整条断言的边界**停下、绝不在字符处截断；连第一条当前断言都放不进这个上限时，这一页干脆不出 ledger 行——被切一半的断言是另一条断言，而这一格是被当作事实读的。两个标签始终分得开，「有人写明了这是什么」不会被读成「这一页恰好装着什么」。
- **deep** —— 以 fast 的证据为种子的有界代理循环，带检索/取原文/读文档工具，预算耗尽强制收束；返回全程轨迹。
- **briefing** —— 在钉住的快照上构建一次、之后反复提问的字节稳定证据包。

L1 词法命中、L2 raw/caption 向量与 L2 episode 描述向量是三条独立排序。每条路径先取最终上限的两倍候选，使后置去重可以从尾部补位而不是缩小召回。普通等权 RRF 奖励多路一致命中，同时让精确的纯词法标识符和日期仍可排在宽泛的纯 episode 命中之前。融合池随后按 `source_id + block span` 做保序重叠抑制；raw/caption 或词法区间与纯 episode 区间重叠时，前者始终保有可引用结果，episode 只能提高它的排名，不能替换更精确的证据。因此多种表示可以提高排序，却不会重复占用答题窗口名额，也不会把一串相邻重叠 episode 串成巨型窗口。任何检索路径都没有固定配额。fast 随后把廉价广度与昂贵上下文分开：产品默认最多召回 80 条 claim 候选与 60 个融合源区间候选，最终调用最多接收 40 条 claim、16 条明确标注的派生 episode 摘要和 6 个逐字窗口。这些是面向交互式个人／团队知识库、与语料无关的经验运行值，不是针对任何特定语料或问题类别的规则。摘要面保留 episode description 的信息密度，较小的 raw 面负责精确措辞与直接核验。fast 响应会把所有准入的摘要回显为 `used_episode_summaries`，并机械标注 `derived=true`、`verbatim=false`；Recall 界面展示同一组元数据，每条都可跳回精确 L0 区间。

fast 还在这些平行视图之上提供可选的**质量编排**档位。使用 `evidence_strategy=select` 时，一次结构化 recall 模型调用会接收带编号的宽 claim／episode／raw 候选与 canonical 一览，并且只返回坐标。框架会拒绝虚构坐标、并入确定性的高排名锚点、执行既有最终上限，再把选中的 claim 与 episode 来源追到有上限且去重的 L0 原文。这只是一次性的查询编排，绝不是新的权威。`answer_format=structured` 可独立启用，将回答类型、干净回答正文和引用分开；只有证据中真实出现过的精确别名区间能够准入。两阶段都可软降级并显式回显原因。selector 串行位于检索与回答之间，因此延迟和 token 成本以 `recall.fast.evidence_select` 单独留痕；候选数和模型在安全锚点前的实际入选数让其真实贡献可观测。每个回答响应都同时携带不含引用的 `answer_text` 与向后兼容的带引用 `answer`。第三档 `evidence_strategy=all` 完全不做选择调用：`select` 本该评判的那个候选池，会以完全相同的证据面、顺序与格式组装好，交给唯一一次回答调用——因此 `used_*` 反映的是全部交出去的内容，`model_selected_*` 保持为零，`select` 阶段回报 `skipped`；它唯一的边界是组装后上下文的字符上限（`RECALL_ALL_CONTEXT_CHARS`），超出时依次丢弃窗口、episode 摘要、排名最低的断言，并在回答上标记 `evidence_selection_degraded="all:truncated"`，绝不悄悄裁剪。在 `structured` 下，它的 schema 以一个有界的 `deliberation` 字段开头，于是那次没有 selector 来做的审视发生在回答调用内部，随回答回传，且从不进入系统消息（I5）。默认 `ranked + text` 路径保持不变。

进入上下文组装后，semantic raw/episode 区间继续保留 ingest 时记录的自然单元，不再二次向前扩张，默认也只合并真正重叠的区间。纯词法单块命中默认只向前扩一块；桥接互不相交的近邻区间必须由调用方显式选择，并经本领域的实际验证。

召回答题绝不因为模型「能看」就自动带入原始媒体。这个成本/注意力决策归属查询 tool，通过枚举列表参数 `include_original_modalities` 明确选择（默认为空；当前支持 `image`）。选中 `image` 时，fast 与 deep 的初始证据会重放附着在已选 L1/L2 正文窗口上的图片：先重新读取并校验不可变的 L0 字节，再加入真实图片 content block。未选中时，fast 仅以文本形式保留带 producer 标签的 caption/OCR 表示，不读取任何原始媒体字节。落在已选窗口之外的图片绝不进入调用，相同摘要的图片会去重，易变的问题仍位于 human message 的最后一个内容块。

fast 面的 claim 检索带两个可选阶段（都默认关；关闭路径字节不变）。**规划**（`RECALL_PLAN_QUERIES`）：一次小调用把多面问题拆成额外的关键词查询，每条查询全强度检索，单次 RRF 融合成池——基于结果的多轮检索仍归 deep。**重排**（`RECALL_RERANK_MODEL`）：core 的 `Reranker` port 对候选池按原始问题打分，最优的 `RECALL_CLAIM_CAP` 条进入提示词——先排后裁，RRF 只保留去重、回填与失败兜底三个职责。内置两个 provider：`llm`（召回角色模型钉在 reasoning effort `none`；输入重、输出微，零额外服务依赖）与 OpenRouter `/rerank` 端点模型名（专用 cross-encoder，按搜索单元计费）。默认关闭重排，因为普通车道已经把宽候选池与有界最终上下文分开；部署只应在同一 harness 的测量支持后开启。候选池另做内容包含去重：相同或被包含的 claim 只留更完整的一条，避免重复入册的事实空耗预算名额。

已启用的索引组件（§6）还可以向 fast 通道提供**路由查询路**。内置路是同质的排名列表，用 RRF 融合；组件路回答的是结构化查询（`person(alias="…")`、`timespan(since, until)`），返回没有排名的精确结果，所以既不盲跑、也不进融合。只要有至少一条路被提供，fast 就花一轮路由 tool call——把这些路绑成工具，一轮里发出零个或多个调用，绝不循环——然后把选中的路与内置检索并发运行，内置检索从不等它。它们的结果构成第四个证据面，在自己的标题下呈现；每个候选都是普通的 claim 锚点或来源区间（I4），引用别名和结构化回答的准入检查原样适用。

一条路返回**它知道的全部**——整页、整段区间——展示什么由 core 决定。先是一次确定性的、不用模型的相关度排序：unicode 感知分词的词面重合、`current`／`superseded` 项、时间接近度，并以路自身的顺序作为并列时的定序；接上重排器时它替换词面重合项，失败则 fail-soft 退回。再把该路声明的上限花在**这个**顺序上，并带两条底线——只要返回过窗口就至少留一个，且每个不同章节至少留最相关的一条 claim。最后用一个字符预算约束整个面（`RECALL_COMPONENT_BUDGET_CHARS`），因为条目数管得住一条路贡献几样东西，管不住它们有多大。每一次截断都被描述而不是仅仅计数：少了哪些章节、哪些日子，过长的摘录按块边界裁剪并写明没展示的块区间。把上限花在文档顺序上，正是那条能回答问题的 claim 恰好掉到边缘之外的原因——所以排序、截断、去重与预算只在 core 里说一次，绝不写进组件：组件决定自己知道什么，从不决定其中多少能进提示词。

去重的方向让排名面不受打扰——它们带着相关度顺序，选择器或重排器已经判过——所以让步的是组件面：它只展示排名面没有的，并说明隐去了多少；排名面上被查询同样命中的 claim 会带上 `via:<path>` 标签：不复制一遍，也把佐证说清楚。在 `evidence_strategy=select` 下，组件结果不再绕过选择器，而是作为自己的一组进入带编号的候选池，被选中的部分渲染进普通证据面。深召回走的是相反的纪律——完整优先于上限：它的组件工具分页，每次响应结尾都给出取回其余部分的确切调用，`timeline` 还能逐块返回某一天的原文，让一天可以被读完，而不是被抽样。路由选了什么、传了什么参数、哪个参数因为畸形被拒、哪条路超时，都是 telemetry，不是沉默——它们和证据本身一起抵达 HTTP 响应和 Recall 界面。没有路被提供、或 `RECALL_COMPONENT_PATHS` 关掉时，就没有路由调用，通道与没有这个缝时逐字节相同。

与组件无关地，claim 面也遵守取代关系（§5）：被正本取代的 claim 标为 `superseded` 并排在活 claim 之后，在拼装时基于通道已 pin 的文档判定，因此一个仍匹配旧措辞的索引不会把历史当成当前状态呈现。

这条通道如今是围着一次并发检索的若干次模型调用，所以它的开销**按阶段**报出：规划、并发检索那一把及其中每条路（claims、windows、概览挑选、每条被路由选中的组件路各一条）、路由那一轮、重排、证据选择、证据拼装、答题调用，以及总计——每一个都把自己实测的墙钟带在结果上，顺序固定，没跑过的阶段也在其中并被标出，于是「慢在哪一段」成为答案自身的属性，而不是主人看不到的一行日志。deep 通道以同样的方式报出，只有一处因形态而不同：agentic 的一次运行没有固定词汇表可对齐，于是它带的是这次运行自己的顺序——每一轮模型思考、每一次围着工具本身量出的工具调用、预算耗尽时那次被迫的收尾，以及收口整个循环的总计——按发生的次序交错排列，因为在那里，顺序本身就是结论。每一步抵达等待中的界面时就已带着自己的耗时，所以一次还在跑的深查当场就是可读的。briefing 通道的两半也照此报出，各按自己那一半的形态：构建是机械的（检索、扩展、按预算拼装，全程没有模型调用），因此发出一套完整的固定词汇表——并与证据包一起持久化，于是几周前构建的那份 briefing 仍说得出时间花在哪儿；提问则又是那个 agentic 循环，它的总计收口的是循环本身而非它所依据的证据包，因为那份包只构建一次、之后一直复用。检索通道——全程不碰模型——也照此报出，用的是四条通道里最短的一套词汇：问题向量、先后两次索引查询、融合、重叠归并，以及总计；一次什么都没找到的检索，秒数照样花在了某处，而一条「便宜到不必解释」的通道是个待验证的说法，不是可以默认的前提。而这份耗时是**边发生边推送**的，不只是事后报出：同一批测量点会在每个阶段开始时、以及落定时各发出一次，于是等待中的读者看着那张图长出来——连模型正在写的答案正文也一起——而不是盯着一个转圈的图标、等到无须再等时才被告知时间花在哪儿。一套时钟，所以边跑边画的和随答案一起到达的，不可能对不上。而在每个阶段的耗时旁边，还挂着一份有上限的**预览**：它拿到了什么、又产出了什么——规划轮写出的检索问法，某一面回了多少条断言、前几条的锚点是什么，路由轮选了哪次查询、参数是什么，拼装时每一段花掉了多少字符——因为耗时只说这个阶段慢，从不说它慢在**什么**上。这个上限是机械的而非劝告式的：每一份预览都要过同一个函数，由它压住序列化后的体积、省略字符串、截断列表，于是一处写得随意的调用点也无法把遥测变成源文本离开知识库的第二条、无上限的通路。

另有 **live context**：给定进行中的对话，每一拍提出零或一张有据可依的建议卡——沉默是常态，不是失败。这里没有人在提问，这一处倒置决定了全部形状：车道不能先花钱检索、再回头判断，因为一屋子人说的话大多不值得查。所以全量范围的一拍分**三段**。**发现**是一次低强度的小型推理调用，而它的职责被写成一条**原则**、而不是一串判例：**替这屋里的人写下此刻最值得问的那一个问题**。它读的是待处理窗口——上次一拍之后说的全部，而不是固定的最后几轮——加上本场已推送过的卡片与主体台账，回答要么是 `skip(理由)`（写不出一个值得问的问题：闲聊、已挖掘、无新内容），要么把那个问题作为*意图*给出，再加一份最多四条查询的「你会怎么去答它」的*计划*——一件要找的事配一条查询，于是一个同时问两个主体的问题会各写一条，而不是把两件事挤进同一条——和一个「这个答案对这屋里值多少」的*价值*分。车道一条条累积出来的规则全都由这一条原则推出：没点名的角色意味着屋里会问*那是谁*，第一次出现的产品名意味着*X 是什么*，找人类需求意味着*这儿谁最懂 X*，而一个被反复提到却从没有人追问的主体，是一个屋里早已知道答案的问题。`intent` 同时就是投递出去那张卡的触发行——正因如此它要照屋里的人能亲口问出的样子写：主体把这一行读作「卡片为什么出现」。跳过意味着这一拍完全没有碰过任何索引；价值低于下限，是同一件事按价格作出的判断。**检索**把计划里的每一条并发跑完——已注册的索引组件（§6）走原本的路由查询路机制，每一条 `semantic` 各做一次自己的断言 + 原文检索，所有查询在一次批量调用里完成向量化，回来后并成一个去重后的候选池——再把结果**机械地**渲染成编号候选卡：断言文本逐字照抄，引用由构造方式自带，全程没有模型。**挑选**是一次关闭推理的弱模型快调用，而它只用**一条**标准：这张候选自己的文本，回答了发现阶段写下的那个问题吗？回答了的就选它，一张都没有就一张都不选；写一句短引言、用屋里自己的话回答那个问题，按编号裁剪该候选自带的引用，并为「那段文本有多直接地回答了它」打分。它从不改写——投递出去的卡片就是那句引言压在候选证据之上，逐字节不变，于是框架是猜测、实质是知识库自己的原话，读者一眼能分清哪句是哪句。

发现这一次调用读到的窗口分成**两部分**，这一刀切开的正是一拍**挖掘**什么与**读懂**什么的区别。待处理那一段的消费语义分毫未动——一拍处理掉它，推送也好跳过也好，下一拍从其后开始——但它上方现在多了一条有界、只读的尾巴：更早的拍次已经处理过的轮次，有自己的小标题，契约明令不得去挖。没有它，意图形成看到的只有新内容：四轮关于苹果折叠屏手机的对话被一次安静的跳过拍消费掉，第五轮独自出现时，产出的意图变成了关于 *Android* 折叠屏的。主题没有变，变的是窗口。

车道挖得多积极，是一个**密度**姿态——`eager` | `balanced` | `quiet`——而且它是一个真正的策略字段，不是三组阈值的名字：阈值只能改变有**多少**通过，永远改变不了去**找什么**。积极档下那句「建议这个事情还是交给我们日本市场的负责人来做吧。」被直接跳过了，因为一个替代无名者的角色不是那一套共用措辞认得出的缺口，不管下限调到多低。它只改变发现契约的一条子句——**那个问题可以有多隐**：`quiet` 下只有有人真的问出口的问题算，`balanced` 下是对话清楚指向的问题，`eager` 下还包括屋里的人自己还没意识到该问的问题（没人停下来解释的说法、替代无名者的角色），而且是与共识规则、already_mined 规则**叠加**而非覆盖。跳过词表与三个输出字段保持共用，所以这是一份契约的三种说法，按（组件集合 × 互联网 × 密度）逐字节钉死。挑选契约不随密度变化：一张卡投递得诚不诚实，不是密度的事。

发现与检索之间还有一道**速览短路**，不花任何模型调用。计划点到某个库里握着的主题时，库其实早就握着关于它的一句有据可依的话——总览的 `definition`，由某次编译写下，画面一变就重写，且落在 ledger 锚上，那些断言自带的引用就是它的引用。这句话立刻原样投出，标为*暂定*，而第二、三阶段照常跑；这一拍尘埃落定时，完整卡要么就地升级它（同一主题、同一格位，队列不增长），要么让它落定、自己排在旁边（不同主题），要么只是把暂定标记摘掉（别的什么都没来）。它过的是与其他卡一样的重复规则与无引用拒绝，并列时谁也不选而不是替你挑一个，跳过更是完全够不到它——正本的那次读取只在真的产生了计划之后才 await，于是这条车道的常态（跳过）依旧什么都不碰。

一个数字管两道门：`min_confidence` 既是发现阶段的 `worth` 下限（低于它就完全不检索），也是挑选阶段的 `confidence` 下限（低于它就不投递）——想少被打扰的部署，两者都想要更少。重复由**主体台账**处理，按会话维护、不花任何模型调用：它统计检索触及过什么、就此推送过什么，把摘要送进发现那一轮（于是一个被反复提到却从没有人追问的主体，会明明白白显示为共识），并机械地拒绝对同一主体的第二次*介绍*——无论那两次调用多有说服力；而关于同一主体的一条*新事实*是另一种卡片，可以通过。简报范围完全不受影响：它的证据是构建时冻结的知识包，没有什么可规划、可检索、可挑选，仍然是那一次调用与它的四道闸门。同一段对话仍有两种投递：对一段已发窗口做一次性评估，以及由长连接在服务端维护待处理轮次、静默期、连接内去重与台账。

在知识库旁边，还可以选装一条**补充的互联网面**——默认关闭，而且只有部署与那一条连接**都**说了「可以」才会打开，于是发现契约恰好在「有东西能服务它」时才写出 `web` 这个查询种类（那份系统消息因此有两种逐字节稳定的形状，两种都被钉死；I5 不受影响，因为这个开关从不进入人类消息）。它有两条被走到的路径，并且分开计数：**planned**——发现阶段规划了它，于是这次搜索与知识库各面并发跑；以及 **fallback**——发现阶段没规划，但知识库给出的候选池是空的，这是唯一顺序执行的情形，之所以顺序，是因为它是一个**结果**：在知识库的沉默被确认之前，没有什么值得为一次按次计费的搜索买单。无论走哪一条，回来的东西都是**同一个编号池里的第 N 张候选**，由同一次挑选调用决定选不选，并在自己脸上写明出自哪个池（`library` / `web`）；而契约按匹配度排序，不按池子排序：一张只是沾边的内部卡，输给一张直接回答意图的 web 卡；反过来也一样成立。它的出处是第二种引用形状——网页标题与网址——刻意与 `Citation` 分开，因为网址不是那套唯一寻址方案（I4）里的地址，一个装着网址的 `Citation` 什么也解析不到，还会悄悄让「一切知识都能回溯到某个来源块」这句话变成假话。知识库那道引用闸门因此不适用于它；适用的是一道装配时的闸门：一个没有点名任何网页的回答，从来不会成为一张卡。这条面被限制在 15 秒内，且失败即软化——一次死掉的搜索只是那一拍记录里的一行降级，绝不会赔上一张卡——它的搜索次数与花费也一并记进那条记录，因为一条按次计费的补充路径必须可读。

一切经由同一寻址方案解析——`source_id + 块区间`——词法命中、语义分块、claim 引用、逐字取文和块级媒体指向同一块序列。答案通过查询局部句柄（`s01`、`s02`…）引用来源，句柄绝不跨一次求值泄漏。检索可以钉在快照上——某个历史版本（只读浏览）或整租户的冻结副本——钉住的查询绝不静默回退到活数据。

## 8. 演进

演进环的全貌：

1. 编译事件持续累积（加了什么、改了什么、在哪里）。
2. 触发条件命中——自上次演进以来的新文档与新 claim 阈值，或手动发起。
3. 框架起草提案：调整文档族、路径模板、页面重组——并在 `evolve/<task-id>` 分支上按新模型重组文库。
4. 人评审 diff：理由、改动文件、以及会因此消失的锚点，全部显式列出。
5. 采纳则经三方、无 LLM 的机械对账合入并重建派生层；丢弃则删分支。草稿有 TTL，过期自动作废。

演进永不改写 claim；演进的是模型——契约、文档族、文库的形状。

## 9. 不变量

七条在代码里处处成立的保证——设计时可以放心依赖它们；改动框架时，它们优先于任何局部取舍。每一条都点名了托住它的那个机制；没有机制托着的不变量只是愿望，这份清单里没有这样的条目。

1. **处处用户隔离。** `user_id` 是每个端口方法的第一参数；每用户独立的正本文库与词法索引；向量库的租户过滤在适配器内部注入，不存在无过滤的公开路径。
2. **正本与派生是不同的类型。** 策略或渲染升级只重建派生物。
3. **L0/L1 可达性无条件**，与 IntakePlan 对 L2/L3 的决定无关。
4. **一套寻址方案。** 一切知识经 `source_id + 块区间` 回链原文；一种引用语法，一个共享解析器。块级媒体经同一地址解析，不走未引用的旁路。
5. **System message 字节稳定。** 易变内容走 human message。
6. **评估绝不渗进被它评估的系统。** 答案、评分标准与预期证据字段只属于 eval 包，而包的依赖方向是单向的：`eval → core`，core 与 service 都不 import 它。编译或召回的输入够不到任何真值文件，因为根本没有这条 import 路径。
7. **组件的投影是派生的，组件永不写正本。** 索引组件索引出的一切，由和其余派生层同一个 `rebuild_derived` 重建；注册时交到它手上的那个正本面是只读的（`CanonicalReadOnly`），所以它的知识只能搭一次普通编译的车进入文库，受契约与闸门管辖。

## 10. 进程拓扑

四个中间件容器（Postgres、Qdrant、Meilisearch、RustFS）加两个无状态进程：

- **API**（FastAPI / uvicorn）—— 摄入、检索、评审界面；同时承载 SSE 流与 live-context WebSocket。
- **Worker** —— 按用户严格串行地排空任务队列（`FOR UPDATE SKIP LOCKED`；每用户同时至多一个在飞任务，这同时就是正本库的单写者保证）。六种任务，组件这道缝一种也没添：`compile`、`index`、`challenge`、`evolve`、`evolve_adopt`、`groom`。组件不是任务，它搭已有的那两种：index 任务告诉每个启用的组件某个来源索引完成，compile 任务则以 `prepare` 开场——正是这一次调用，让组件那些同步的缝读得到另一个进程写下的投影。重启时自动回收孤儿任务；任何异常都以失败完结，绝不留下悬挂的占用，而一次挂死的模型调用由 `COMPILE_CALL_TIMEOUT` 兜底，断掉的连接不会把一个 worker 占到下次重启。

Git 二进制是运行时必备（正本适配器通过子进程调用它）。异步纪律贯穿全栈：端口及一切触及端口的代码都是 `async`；纯计算辅助函数保持同步；不可避免的阻塞操作（git 子进程、分块）在适配器内包线程执行。

模型接线按角色划分——compile、recall、answer、deep、skill、evolve、challenge、live-context——各自独立可配，带一跳回退和共享默认值。`recall` 负责检索规划/概览，`answer` 只负责 fast 最终答题，因此质量优先的推理不会拖累每一次检索辅助调用。`scripted:` 模型规格回放录制好的响应，用于零密钥、确定性的运行；向量模型同理接受确定性的 `fake:<dim>`。追踪（Langfuse）在未完整配置时整体为空操作。

## 11. 引擎目录

一个部署里「构成引擎本身」的东西——策略、编译契约、提示词覆盖、主人档案——可以住在同一个目录里，作为它自己的 git 仓库被版本化，与数据、密钥、机械件分开。`PNEUMA_KNOWLEDGE_ENGINE_DIR` 指向它；不设（默认）就表示这个部署没有引擎目录，所有策略键的解析与这个概念存在之前逐字节一致。

```
engine/                    # 自己的 git 仓库；每次 apply 一个提交
  engine.yaml              # 模型角色 · 编译图片交付模式 · 编译调用超时 ·
                           # 总览预算 · 启用的索引组件 + people 文档族
  intake/intake.yaml       # chunk_strategy, semantic_overlap
  compile/contract.md      # 宪法——一份文档，永不被拆成旋钮
  compile/challenge.yaml   # 覆盖质询的旋钮
  evolve/evolve.yaml       # 演进触发的旋钮
  recall/recall.yaml       # 回答风格、检索预算、组件面自己的预算，
                           # 以及 fast 是否路由到组件查询路
  persona/profile.yaml     # 主人档案
  prompts/overlays.yaml    # 提示词语言 + 目录键 → 替换文案（提示词扩展点）
```

三条性质让它成为机制而不是约定：

- **优先级固定为三级：进程 env > 引擎文件 > 框架默认。** 显式环境变量优先，好让运维方可以做临时的进程级覆盖，而不脏化被版本化的单元；引擎文件是人真正在编辑的、持久的那份真相。这条规则在 settings 装配处被机械执行——引擎文件的值只在环境未表态的键上被交给 `Settings`。
- **密钥与基础设施永不进入。** 连接地址、端口、API key 留在部署的环境里；任何写入都会拒绝点文件路径与形似 API key 的内容。
- **图是导出的，不是画出来的。** 一份机器可读的引擎 schema（各阶段、带默认值与 env 名的旋钮、生效语义、流水线连边）由 `Settings` 元数据加一份手写的阶段地图生成，并有测试把两者钉在一起——新增策略旋钮而未被覆盖，测试就红。

每一次编辑都要说出自己的影响半径，这就是把不变量 I2 摆到明面上：`hot`（下一个读这些文件的进程即生效）、`restart`（API/worker 需要重新接线）、`future_compiles`（只管未来的编译；正典永不被回溯重写）、`derived_rebuild`（对已有内容要跑 `rebuild_derived` 才完全生效）。契约始终是一份带版本历史和编辑器的文档，绝不是一堆开关：知识建模是判断力，把它装成打勾式配置，是这个框架唯一负担不起的谎。完整设计见 [docs/design/engine-console.zh-CN.md](design/engine-console.zh-CN.md)。
