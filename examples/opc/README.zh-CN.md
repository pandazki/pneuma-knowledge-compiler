# OPC —— 一个由代理建成的完整知识库

[English](README.md) | **简体中文**

这个目录就是 scaffold 流程的产物：一位合成所有者——**林舟**，一个人做变更证据链产品 Seamlog 的独立开发者——的知识库项目，191 份来源编成 28 篇正本文档、1188 条带引用的知识。库随项目发行，不需要 API key，一分钟就能在浏览器里打开。

## 它是怎么来的

这座库遵循的契约，是一个**自主代理**（在 Claude Code 里跑的 Claude Opus 5）写的：它从一份干净的 [`scaffold/`](../../scaffold/) 出发，照 [`AGENT-GUIDE.zh-CN.md`](../../scaffold/AGENT-GUIDE.zh-CN.md) 走，输入只有两样——`my-data/` 里的材料，和所有者三句话的自述。它通读了全部 190 份，从读到的东西推出 [`engine/compile/contract.md`](engine/compile/contract.md)，编译，按[验收环](../../docs/guides/compile-contract.zh-CN.md#8-验收环)判定结果，并在第一轮违反了材料自己立下的一条规矩时用掉了它唯一一次改契约的机会。

契约在新机制需要判断的地方被**扩写**而不是重写：所有者自己的话算什么、每一族的总览头部该写什么、什么算一个人的称呼。[`build-record/`](build-record/) 记着这次构建：任务书、构建日志、成本账，以及那次「使用侧」会话——访客留下的记录就是它产生的。

这次构建是**一条参考线，不是天花板**：它是某一代代理在某一批语料上做出来的结果。把同样的数据和同样的指南交给更强的代理，库很可能更好——契约判断力正是代理之间拉开差距的地方。

## 上手

**1. 浏览——不需要 key**

```bash
cp .env.example .env
./app.py up && ./app.py restore
docker compose --profile console up -d --build   # 第一次构建镜像要几分钟
```

打开 <http://127.0.0.1:24173>。一切都能钻下去：191 份来源逐字可读、编译历史、每条知识回到原文的确切段落，以及产出这一切的那台引擎本身。

**2. 提问——需要 key**

`.env` 里填上 OpenRouter key（`OPENROUTER_API_KEY`），调模型的那几条通道就打开了，命令行和浏览器都一样：

```bash
./app.py ask '第一条证据链现在卡在什么条件上？' --sources
docker compose --profile console up -d api            # 浏览器里的问答通道
```

**3. 用你自己的参数重编——需要 key，花真金白银**

改 `engine/`（契约、模型、组件）再从同一批材料重编，正是把引擎和库一起发行的意义。参考构建花了多少，账在 [`build-record/`](build-record/) 里：

```bash
./app.py down --volumes && rm -rf data/
./app.py up && ./app.py init
./app.py ingest my-data && ./app.py compile
```

`./demo.sh` 把这三段包成一个交互菜单。

## 这个示例现在还展示什么

库只是一半。另一半发生在库之上：谁在动这座库、这一动留下了什么、以及它花了多少钱。

**身份是一个身份，不是每次提问的一个选项。** 左栏底部一个开关——所有者／访客／无痕访客——同时决定控制台显示什么、以及它的问题带着哪一类。所有者是驾驶舱：所有视图。访客与无痕访客是阅览室：问答界面加只读浏览，别的没有。用访客身份深链到驾驶舱的某个视图，会落回阅览室。

**提问按身份被记录，账本当场就在长。** 所有者和访客都以 `business` 提问——在这里问一句就是这座库被用了一次，而一次没人记的使用会让库把自己报告成无人问津。无痕访客以 `silent` 提问，并在徽章和页面上说明这一点。咨询视图（§08）列出问过什么、哪些证据被交出去、哪些问题空手而归、每次回答花了多少。`build-record/use-side/session.json` 是第一次把它填满的那一轮：六个 business、一个 audit、三个 silent——而那三个 silent 在账本里根本不存在，这正是「静默」的意思。

**每一页都说得出它上次被读是什么时候。** 每篇文档带一张访问卡：上次访问、近 7 天与近 30 天的命中，以及一个按 14 天半衰期衰减的热度。没有任何分数被存下来——热度是读取时算出来的，改半衰期不会改写任何东西。咨询列表上方的使用面板给出同一本账的总账：最热的页、空手而归的问题，以及这个窗口的花费。

**所有者靠对库说话来订正它。** `engine/compile/contract.md` 第 3 节写明一段所有者陈述算什么；控制台的「所有者陈述」表单把它作为一份普通来源发出去（`owner-dialogue/v1`）——像邮件一样被引用，像别的材料一样被编译。在这座库里，林舟说一笔账本记着「未到」的尾款已经付了；编译引用他这段话取代了那条过时的知识，被取代的那条逐字不动地留在原处。历史视图把它标为一次取代，页面上两条按先后并存。

**Live Context 是在听一场对话，不是被提问。** Live Context 视图逐轮读进一段对话，当对话给出足够的抓手时，从库里递上一张带引用的卡片。它每一跳的遥测会说这一跳花了什么。

**钱花在哪。** `engine/engine.yaml` 声明这个部署为它那四个模型付多少钱——这是价格进入系统的唯一入口；没被声明过价格的模型只报 token，旁边不写金额，而不是写个零。编译是数量级意义上最大的开销，流程视图上每个编译任务都带着自己的 token 与费用；咨询视图带着回答那一侧。Live Context 的每一跳故意只显示 token 不显示钱：它那两次调用跑在这台引擎定价不同的两个模型上，而一跳的用量里没有按角色的拆分，所以在那里写一个金额，就是给编造的钱套一个「算出来的」标签。

**回答一个问题花多少，以及为什么是这个数。** 这个例子用 `evidence_strategy: select` 回答：在这样一个小语料上检索分数几乎是平的，「排名前六的窗口」近乎是随便的六个，一次选择调用因此值这个价。代价是每个问题多一次串行模型调用，深车道则更贵。每条车道在这里实际花了多少，记在 `build-record/use-side/session.json` 里——测出它的那一轮就在旁边。要改就改 `engine/recall/recall.yaml`，只改一次提问则用 `./app.py ask '…' --evidence-strategy ranked`。

## 这批语料

`my-data/` 是一个人 84 天的工作现场，全部合成（没有真实人物、品牌或凭证）：18 场会议与 48 段即时消息以转写形式存在，81 篇笔记与 43 组邮件线索以文档形式存在。它最要紧的特征——也是它适合用来考验这套框架的原因——是其中近一半的信息是**否定事实**：什么没有被批准、没有签、没有确认、没有找到。一个把「提议」压平成「决定」的编译器会把这批语料变成虚构；随库发行的那份契约，存在的意义正是不让这件事发生。

## 回归评估

`eval/opc-truth.json` 是一份冻结在这批语料上的真值集，`eval/run_eval.py` 拿它给一座建好的库打分。它存在的理由是：「库变好了」这句话没法从 diff 里看出来——要说后来的契约或框架改动让这一版更好，只有一条路：同一批问题、同一批材料，和一条已提交的基线相比。

**它覆盖什么。** 83 道题。八条正向轴——当前状态、历史、链完整性、闭集枚举、定义、日历、聚合、跨页多跳——另加 22 道反向题，分三种形状：语料确实从未记过的细节；根本不存在的对象（真名的近似词：云岭之于云麓，陈昉之于陈放）；以及自带错误前提的问题。每道题都带一个难度档，L1（只写在一处的事实）到 L5（一条链走到底）。问题之外还有一条结构探针：材料禁止把两条证据链的状态合成一个总的通过标记，所以承载其中一条最多的那份文档，不能同时是承载另一条最多的那一份。

**一个回答怎么被判。** 每道正向题的应答被拆成若干「面」（facet），一个面只说一件事，各自标注 `core` 或 `detail`：所有 core 面都被说出来，这道题才算对；detail 面单列一行计分，所以一个答对了所问的答案，不再因为没多说没被问的东西而判错。每一个面都由 LLM 判官裁定，只报 `stated`（说了）、`omitted`（漏了）、`contradicted`（说反了）三者之一，让「说得少」和「说错了」分成两件事；判官被问的是蕴含而不是字面，换一种说法说到了就算说了。一个面可以在命题之外另带一份 `examples`，并告诉判官这份清单是什么：它是「什么样的东西能满足这个命题」的举例，不是核对表。

**一次拒答怎么被判。** 反向题的虚构审查官会先读到答案自己引用的那几段 L0 原文，所以一条有引用支撑的细节不会被当成编造；它还被告知，交给它的那句「材料里没有」为真——顶回一个前提只能靠把否定说出来，所以答案说出那份缺席、或说出与错误前提相反的那条材料事实，是在纠正提问，不是在编造。带错误前提的题还多一条 `premise_accepted`，因为顶回一个前提和编出一个数值是两种不同的失败。对象根本不存在的题，界线画得很明确：把一个数值交给那个虚构对象、又不指出它真正属于谁，就是在虚构对象里面作答，哪怕全程避开「它存在」这句话，也算编造；而把问题纠正到真实对象上，或者干脆拒答，都不算。

**真值的基准是这个示例自己的输入**：`my-data/` 的 190 份材料，加上 `build-record/exercise.py` 送进去的那条所有者陈述——第 191 份来源，开发者恢复这座库时它也一起进来，正是它让尾款从一个悬着的问题变成一次取代。写题时没有打开任何正本文档，所以这套题不会奖励这一版自己的措辞；446 条引文在打分之前逐条与摄入后的 L0 对齐，有一条对不上就停下。

**那条命令。** 需要栈已启动并恢复（`./app.py up && ./app.py restore`）。

```bash
# 无需 key：编译轨迹上的 A–E 组，加上结构探针
uv run python eval/run_eval.py --mode mechanical --out var/eval

# 有 key：再加上 83 道被真实作答的题、逐面判定和反向题组
uv run python eval/run_eval.py --mode full --out var/eval
```

它接受 `--api`、`--user`、`--canonical`，所以能给这个示例的**任何**一次构建打分，不只是随包发出的这一次。提问用的是无痕访客身份：给库量尺寸不是在用库，无痕提问不留咨询行，所以跑这套题永远不会改写注意力账本。多数题走 fast 一路；聚合、多跳，以及真值被契约留在原始材料里的那几道，两路都跑，分路报数，不做平均。full 模式下的提问与判官调用花的是等待而不是算力，所以它们在一个有上限的并发下发出——`--concurrency N`，默认 32，`1` 就是串行；结果按真值集的顺序重新装配，因此这个上限只动墙钟时间，不动任何一个分数。

**纪律。** 参考线在 [`build-record/eval/`](build-record/eval/)，如实记下，来什么记什么；每一条旧基线按日期另存一个子目录，和当前这条并排放着，那条线答得出什么、答不出什么也写在那里。质量结论是那个「比」，不是那个数：拿同一条命令跑你自己的构建，再和那条基线相减（AGENTS.md——成本与质量分开测量，质量结论需要同一套测量装置下的基线）。记分卡刻意没有总分，也没有及格线，基线也不是目标。

## 用你自己的代理复现它

这个示例的全部意义就在于你能复现。把 scaffold、两份指南（[契约](../../docs/guides/compile-contract.zh-CN.md)、[AGENT-GUIDE](../../scaffold/AGENT-GUIDE.zh-CN.md)）和 `my-data/` 交给一个编码代理，让它走同一条路——`build-record/TASKBOOK.md` 就是启动参考构建的那份原文。预期得到一座形状相近、但不会一模一样的库：它推出哪些主体族、定下什么口径，是它自己的判断。
