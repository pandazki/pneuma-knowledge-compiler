# Knowledge Transit Atlas surface brief

- Scope/mode: whole React surface; Operate with a guided Read layer for first-time
  open-source visitors.
- Audience/job: an OPC AI-native developer should understand the architecture in one
  viewport, replay the synthetic demo, then inspect one source-to-canonical-to-Git
  journey without learning eleven admin screens first.
- Direction: **Knowledge Transit Atlas**. Authoritative and rebuildable layers are
  colored routes; source, index, compile, canonical, and Git are stations and
  interchanges. The interface refuses the category-standard dashboard grid and exposes
  forms only inside task-specific station sheets.
- Selected composition: `.impeccable/mocks/transit-open-source-stage.png`, carrying the
  route-detail clarity of `.impeccable/mocks/transit-route-overview.png`. It wins because
  the architecture itself becomes the first-viewport artifact and each experiment begins
  at a named station rather than a generic form page.
- Memorable moment: selecting an Atlas source lights one continuous route through
  retrieval and compile gates, then opens a destination sheet containing the exact
  source span, canonical claim, and Git commit.
- Themes: light = porcelain wayfinding mural under daylight; dark = midnight enamel
  transit control room. Route identities and station states remain semantically stable.
- Responsive commitment: desktop renders the branching SVG; 820px and below renders the
  same six stations as a complete vertical route. The 390px acceptance viewport keeps
  S0, P0, L1, L2, C1, and G1 present and operable.
- Disclosure commitment: `SYNTHETIC` remains visible in desktop navigation, mobile
  navigation, and the opening manifest; bundled persona, counts, and evidence are
  repository-derived simulations, not customer proof.
- Constraint: preserve the Pneuma mark and recognizable grouped navigation; no private
  business/device assumptions, KPI theatre, checkerboard texture, dense admin grid,
  bento dashboard, fake evidence, or decorative neon routes.

## Open-source demo journey

1. **System map:** understand authority, rebuildability, stores, and compile boundaries.
2. **Replay demo:** restore the deterministic OPC dataset and watch the active route.
3. **Run an experiment:** import material, run recall, or evaluate a context suggestion from a
   station sheet.
4. **Verify provenance:** trace one answer or claim back to source and forward to Git
   history.
5. **Explore internals:** branch into sources, indexes, canonical documents, graph,
   history, and strategy evolution only when needed.
