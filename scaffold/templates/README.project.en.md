## Which files are yours, which to leave alone

**Yours (edit freely):**

| File | What it is |
|---|---|
| `engine/` | **The engine itself — yours, and versioned**: model roles, chunking, answer style, the audit and evolution switches, the compile contract, your profile, prompt overlays. Its own git repository, so every change is a version you can read back and revert. Start at `engine/README.md` |
| `engine/compile/contract.md` | The compile contract — this library's constitution: what deserves memory, on which page. {{CONTRACT_HINT}} |
| `engine/persona/profile.yaml` | Your owner profile (name, occupation, timezone/language) |
| `.env` | The key and this machine's infrastructure (ports, compose project). The key goes here only, never committed; no strategy lives here |
| `my-data/` | Your material (`.md` files with `date:` frontmatter) |

Strategy and secrets live apart because `engine/` exists to be versioned, shared and
reverted, while `.env` holds a credential and must never be. Any `PNEUMA_KNOWLEDGE_*`
environment variable overrides its counterpart in `engine/` for one run — that is for
experiments; the durable answer belongs in the file.

**Machinery (do not edit — changes are lost on upgrade):** `app.py`, `start.sh`,
`docker-compose.yml`, `server.py`, `worker.py`. They are the framework's runtime drivers and all logic lives in the
framework repository; to upgrade, regenerate a project with the framework repo's
`scaffold/init.py`, or copy the latest from `scaffold/templates/`.

## Commands

```bash
./start.sh                   # end to end in one command: stack → detect → ingest → compile → demo Q&A
./app.py up                  # start the middleware stack (ports live in .env — free ports probed at
                             #   generation time, echoed on startup)
./app.py init                # detect timezone/language from the system into profile.yaml
./app.py ingest [dir]        # ingest material (defaults to my-data/)
./app.py compile             # drain the compile queue (real models — the step that costs money)
./app.py ask 'question'      # fast-path Q&A (--sources also prints the cited raw passages;
                             #   --style concise|conversational|detailed overrides the answer style)
./app.py glance              # bird's-eye view of the library (no key needed)
./app.py evolve [action]     # schema evolution: list / run / show / adopt / drop proposals
./app.py status              # stack and library status (no key needed)
./app.py restore             # restore the prebuilt library this project ships, when it ships
                             #   one (prebuilt/ — no key needed)
./app.py down [--volumes]    # stop the stack (--volumes also deletes the data volumes)
```

## In a browser

One command starts the browsing layer — the framework API, a compile worker and the web UI,
all built from the framework repository named in `.env`:

```bash
docker compose --profile console up -d --wait    # the first image build takes a few minutes
# then open http://127.0.0.1:<PNEUMA_APP_WEB_PORT from .env>
```

Three things to do there: read the library (every claim drills back to the exact source
passage), watch the process (how material became claims), and open the **Engine Console** —
a projection of the `engine/` directory: change one knob, read its blast radius, apply once,
and the timeline gains a version. No key needed to look: the library, its sources and every
citation are fully readable; only asking and compiling need one.

## Reset

```bash
./app.py down --volumes && rm -rf data/
```

Use after rewriting the contract to recompile on a clean slate (removed subject families
are never migrated automatically; an empty library is the clean way). `engine/` is untouched
by this: it is your engine, not your data.
