## 1. 上一轮之后，框架变了什么

第一轮编出这座库的时候，框架还没有下面这些东西。它们都不是"更多功能"，而是这座库
本来就该有、当时还没有的部位：

| 长出来的东西 | 对这座库意味着什么 |
| --- | --- |
| **总览头部**（`rewrite_overview`，四个槽位） | 每一页在账本之上有了一段有界的画像。上一轮的页面只有账本：知识都在，形状要靠读者自己拼 |
| **取代**（`supersede_claim`） | "世界变了"与"我记错了"分成了两个动作。上一轮只有订正，一条过时的状态只能被改掉，改掉就没了 |
| **索引组件**（`people` / `time` / `attention`） | 人物页有了 `identities` 与 `aliases` 并在闸门上被检查；来源有了所有者日历里的跨度；被问过什么变成一本可读的账 |
| **访客身份与咨询记录** | 提问这件事第一次留下痕迹：`business` 记录并投影，`audit` 只记录，`silent` 什么都不留 |
| **`owner-dialogue/v1`** | 所有者对库说的话成了第五种官方来源：像邮件一样被引用，像别的材料一样过闸门 |
| **Live Context** | 库可以听一场对话，而不只是被提问 |
| **成本可见**（模型定价声明） | 每个编译任务、每次咨询都说得出自己花了多少 token、按本部署声明的价格值多少钱 |
| **引擎目录** | 模型、价格、组件、切分、回答、契约、所有者档案收进一个可版本化的 `engine/` |

示例项目自己也落后了四波：它还带着"前引擎时代"的机械件，Web 镜像用 mock fixtures
构建，控制台打开的是它自己的赝品。重建这座库，正好是把这一切一起改正的时机。

## 2. 这一轮按什么配置跑

引擎目录 [`engine/`](../engine/) 是唯一的策略来源，`.env` 里只有 key 和这台机器的基础设施。
关键几项：

| 键 | 值 | 为什么 |
| --- | --- | --- |
| `compile` / `recall` | `openrouter:openai/gpt-5.6-luna` | 与第一轮同一个模型，好让"库变好了多少"不是模型换代的功劳 |
| `deep` | `openrouter:openai/gpt-5.6-terra` | 深检索是多轮推理，这一档值它的价 |
| `live_discover` / `live_pick` | `gpt-5.6-sol` / `gpt-5.6-luna` | Live Context 一跳是两次小调用，一次要判断力、一次只要快 |
| `embedding` | `openrouter:openai/text-embedding-3-small` | 1536 维；无 key 时框架换成同维度的确定性向量，所以浏览不需要凭证 |
| `pricing` | 四个模型的真实 OpenRouter 挂牌价（2026-09-01） | 框架自己不持价格观点，这里是本部署自己的声明 |
| `components` | `people,time,attention` | 三个都开；`people_family` 绑到本契约的 `people/{slug}.md` |
| `chunk_strategy` / `semantic_overlap` | `semantic` / `smart` | 与第一轮一致 |
| `prompt language` | `en` | 框架自己那套措辞留在被测过的基线上；这座库写什么语言由所有者档案决定，不由这里决定 |
| `challenge` / `evolve auto_trigger` | 关 / 关 | 这一轮不做覆盖审计，也不让结构演化自己开火——两者都会花掉不属于这次构建的钱 |

## 3. 契约：`lin-v2` → `lin-v3`

第一轮那份契约的判断力没有被重写，只在新机制真的需要判断的三处扩写。

**（1）所有者自己的话算什么**（第 3 节）。`owner-dialogue/v1` 是林舟对这座库直接说的话。
它提到某条已入册的知识时，就是关于那条知识的证据：引用这段陈述去订正或取代它，
不要在旁边再记一条自相矛盾的。两个动作在契约里被分开写清楚——记错了是订正，
世界变了是取代，取代要引新证据、被取代的那条逐字留着。并且加了一句限制：
所有者的陈述不因为出自所有者就免于口径，它能改的是这座库的记录，不能改客户那一侧发生过什么。

**（2）每一族的总览头部该写什么**（第 1 节）。区域大小、每块都要有引用、不许指向不存在的页，
这些是机制，契约一句都不重述。契约只定措辞：人物页的 `definition` 写这个人在这批材料里
说话的位置而不是职务头衔；客户页的 `summary` 必须落在当前授权到哪一步、明确不覆盖什么；
链页的 `connections` 不许把另一条链写成佐证；工作线页的 `summary` 写卡在什么条件上、在等谁。
最后一句是这批材料的老规矩换个地方再说一次：**头部不许比账本说得更满**。

**（3）什么算一个人的称呼**（第 1 节）。`people` 组件开着，它会把全库对在场者集中使用的
称呼词报到每份来源下面，要求本轮逐项裁定。这条判断这批材料早就付过学费了——本周期最大的
事故正是从"名称相近就足以作身份依据"来的——所以契约把判据定死：名称相近、同姓、
工单抬头里写错的姓名，一律 `decline_alias`；职务称谓也不是别名，因为换个人坐这个位子
还这么叫。

- **十个问题，七条记录。** 六个 `business`、一个 `audit`、三个 `silent`。三个 silent 的
  问题在账本里根本不存在——这正是"静默"的含义，不是一个标记，是没有那一行。

  `answer_kind == "no_record"`，或者根本没有证据到过模型面前——后一半对每条通道都成立，

  `engine/recall/recall.yaml` 里显式写了 `answer_format: structured`；用默认的 `text`，
  一个明明检索到了证据、却答不出来的问题只会被记成一次普通咨询。
- **388 行访问记录。** 被读得最多的是 `threads/old-material-request.md` 与

- **所有者说了一句话，库改了。** 林舟通过 `owner-dialogue/v1` 陈述尾款已于 8 月 29 日到账、
  金额 5400 元、并强调附录签字与删除演练两项仍然没有答复。这段陈述作为第 191 份来源入库，

- **Live Context 听了一段三轮对话**（eager，每轮 flush），8 个帧记在会话记录里。

一句如实的记录：这个脚本第一次跑到一半被外部超时打断，已经写下的咨询行在重跑前被清掉、

## 7. 成本账

价格是这个部署自己声明的（`engine/engine.yaml` 的 `pricing`，取 2026-09-01 OpenRouter 的
挂牌价），框架自己不持价格观点。

| | token | 按声明价格 |
| --- | --- | --- |
| 编译（382 个任务，记在任务行上） | 45.19M in ／ 581k out | **$9.73** |
| 编译（驱动器计的全部编译角色调用，含切分） | 45.50M in ／ 753k out | — |
| 回答（7 条咨询：6 business + 1 audit） | 见会话记录 | **$0.14** |

两件必须说明白的事：

1. **这个金额是上界。** 编译循环把每一轮的用量按 `input_tokens` / `output_tokens` /
   `total_tokens` 三项相加，从不读 `input_token_details`，所以一个编译任务的
   `cache_read` / `cache_write` 恒为 0，全部输入都按满价计。实际账单只会更低。
   （`input_tokens` 本身是整个 prompt、含缓存部分，所以 token 数不受影响。）
2. **贵在哪里。** 一次编译的输入从第一批的约 8 万 token 长到后期的约 30 万：编译是一个
   工具循环，每一轮都要把整段对话重发一次，而这一轮的对话里多了总览头部的读写、
   三个组件的来源前言、更多的工具描述，以及编译结束时的那份简报。同一批材料、
   同一个模型、同一份判断力，token 是上一轮的 2.2 倍——**这是新机制在这批语料上的价钱**，
   不是某处失控。

**另有一次被中止的尝试，如实记在这里。** 这一轮之前先跑过一次没有钉住 provider 的构建，
在第 80 个编译任务、12.52M token（声明价 $2.74）时按任务书的成本闸停下并作废。停的原因
是投影超过基线的 1.5 倍；作废的原因是它违反了一条既有裁定——经 OpenRouter 走的 GPT 系列
必须钉在官方 provider 上。那次的逐行记录留在
[trace/compile-unpinned-stopped.txt](trace/compile-unpinned-stopped.txt)。

两次跑的前 80 个编译任务是一次干净的 A/B：

| 每 10 个编译任务的平均输入 token | 未钉住 | 钉住 `openai` |
| --- | --- | --- |
| 1–10 | 103,667 | 79,767 |
| 11–20 | 108,200 | 112,024 |
| 21–30 | 125,882 | 126,417 |
| 31–40 | 140,925 | 106,013 |
| 41–50 | 211,811 | 170,151 |

## 8. 如实记下的几件事

**1. 两条证据链被编进了同一页——这是这一轮最重要的一处退步。** 契约第 1 节把"每条链
各自一页，永不合并"称作本库最硬的一条归属规则；上一轮编出了两页——预算变更 15 条、材料替代 12 条
（`chains/material-substitution.md` 里出现"预算"的地方，全都是材料自己那句"不借预算链补它
自己的来处"）。这一轮只有 `chains/material-replacement.md` 一页，
预算调整链的节点作为其中一节（`## 2026-05-12 预算调整状态与链间边界`）写在里面。
页内的口径守住了——它反复写明"不构成两条链均已验收"——但**结构没守住**：材料里
"两条的状态不要合成一个总的通过标记"这句话，这一轮没有变成库的形状。契约的措辞没有变，
所以这是同一份判断力在两次运行之间的方差，不是契约写错了；要让它稳定下来，得给这一族
一条比散文更机械的规矩。

**2. `people/nishan.md` 只有 1 条 claim 就立了页。** 契约写的是"第二次带着实质信息出现才
立页"。倪珊只出现过一次。同上：措辞在，判断没落地。

**3. `identities` 字段全库为空。** 这批材料是以文档与对话的形式摄入的，不走
`meeting/v1` / `im/v1` 那两份来源契约，所以没有任何账号级的人物标识可绑——组件老实地什么
都没写。`people` 组件在这座库里贡献的是闸门检查、称呼词裁定和 `find_person`，
以及一张 31 行的称呼词投影；identities 那一半在这批语料上无从谈起。

**4. 这个示例的 `engine/` 不是它自己的 git 仓库。** 生成的项目里它是；在框架仓库里，
一个嵌套仓库会让外层只存下一个 gitlink，引擎文件反而读不到——而开发者打开
`examples/opc` 就是为了读那台引擎。所以这里的引擎文件归框架仓库管，控制台自己的提交
落在一个被 `.gitignore` 忽略的 `engine/.git` 里，由框架在第一次 apply 时创建。

**5. Live Context 的每一跳只显示 token、不显示金额。** 它的两次调用跑在
`gpt-5.6-sol` 与 `gpt-5.6-luna` 上，这台引擎给这两个模型定了不同的价，而一跳的用量里
没有按角色的拆分。框架在这种情况下拒绝给出金额——这是设计，不是缺口。

**6. 署名与落款各自成为一个单行块，内容块因此不带身份——记录，不在本轮修。**
文档类来源（`document-library/v1`）摄入后，抬头、落款、发信人各占一个只有一行的 L0 块，
而承载内容的那几块里一个名字都没有。这批语料里到处如此：《保养取车窗口调整》是
¶0「林先生：」、¶3「常青养护前台」、¶4「前台：」、¶8「林舟」，内容在 ¶1–2 与 ¶5–7；
《今日取车未能交付》的「桥桥保养站」在 ¶3；《保养报价中的基础项目》的「北巷保养咨询」在 ¶4；
《邀请发出前：两个链接回查》两封信的收发双方分别落在 ¶0、¶5、¶6、¶11，而"我按待发信里的
顺序从头点了一遍"这句在 ¶1，句子里没有主语。

后果是一类问题只靠检索走不通：「这批材料里出现过几家保养商家」要把商家名和它签发的内容绑起来，
「某某在工作那一侧做过什么」要把一段行为绑回做这件事的人——而窗口取到内容块时不带名字，
取到名字时那是一个孤立的单行块，在任何排序里都很难自己浮上来。回归集里
`aggregate-01`（三家商家，两条车道都只答出一部分）与 `join-03` 正是这个形状。

这是**框架层**的观察，不是这个示例的配置问题：它落在 `document-library/v1` 的来源前言
与块归属这一段（编译任务里的 source preamble，以及块级的发信人/收信人归属），
本轮只记录、留给维护者，不在这里改——改它会动摄入产物，而这一轮的所有数字都建立在
当前这批 L0 之上。
