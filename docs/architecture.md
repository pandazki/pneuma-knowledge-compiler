# Architecture

**English** | [简体中文](architecture.zh-CN.md)

The whole system on one page: what it commits to, how data flows, and what is mechanically enforced. Everything else under `docs/` elaborates a section of this page.

## 1. Design stance

Three commitments define the system; each is enforced by a mechanism, not by convention.

**Domain-oriented modeling.** The framework holds no domain opinion. `load_skill_base` raises unless the deployment has registered a compile contract, and the only required setting (`PNEUMA_KNOWLEDGE_USER_SCHEMA_BASE_VERSION`) exists to force that declaration. What gets recorded and in what structure lives in a contract you write — a markdown file plus path templates — while the framework supplies only domain-agnostic machinery: normalization, indexing, retrieval, verification.

**An evolvable model.** Any model fixed up front degrades as data accumulates, distributions shift, and the business pivots. Evolution is therefore infrastructure, not an afterthought: the compiler records events as it works; the framework drafts schema changes from that history on a branch; a human reviews the diff; a mechanical, LLM-free reconciliation merges what was adopted (§8).

**Provenance enforced at the write layer.** The compile model has no whole-file write tool. It works one claim at a time — append a claim, correct a claim, or record that a new claim supersedes what an older one said — and every claim must carry citations that resolve to exact passages of source material. The single region it may replace wholesale, a document's overview, is bounded and may hold nothing the ledger below it does not already carry. A gate verifies all of that mechanically before anything is committed (§5). Fabrication is not discouraged; it is structurally impossible.

One boundary: this is not an agent memory system. An agent's memory should record that it *has* a knowledge base — how it is built, what it roughly contains, how to query and maintain it — not the knowledge base itself.

And one project-wide discipline behind all three: **mechanism over persuasion**. A constraint that matters is implemented as write-time rejection, system-assigned identity, or deterministic normalization — never as prompt copy asking the model to please remember. If you find yourself writing that prompt, the design is wrong.

## 2. The shape of the system

```
 raw material ──▶ SourceAdapter ──▶ NormalizedSource ──▶ IntakePlan
                                                            │
              ┌─────────────────────────────────────────────┤
              ▼                                             ▼
        index jobs (L1/L2)                          compile jobs (L3)
              │                                             │
              ▼                                             ▼
   Meilisearch / Qdrant                     canonical library (versioned)
              │                                             │
              ├──────────▶  index components  ◀─────────────┤
              │             derived projections             │
              │             · gate checks · tools           │
              │                     │                       │
              └──────────────┬──────┴───────────────────────┘
                             ▼
            retrieval lanes: rag · fast · deep · briefing · live context
```

An **index component** (§6) is the optional third box: business-specific structure derived from the same L0 and the same canonical library, contributed by the application rather than by the framework. It reads both, writes only its own derived projection, and offers what it indexed to the write gate, to the compile model and to the retrieval lanes. With none enabled the diagram is the two columns it has always been.

Four packages, one-way dependencies:

- `pneuma-knowledge-core` — pure domain logic and async `Protocol` ports. Depends on pydantic, langchain-core, langchain, chonkie; **no middleware clients**. LLMs and embeddings enter as langchain-core types (`BaseChatModel`, duck-typed `Embeddings`).
- `pneuma-knowledge-service` — the port implementations: FastAPI app, adapters (Postgres, Qdrant, Meilisearch, S3-compatible media, Git-via-subprocess), the background worker, settings.
- `pneuma-knowledge-strategies` — reference compile contracts as a data package. The framework never imports it.
- `apps/web` — a SPA speaking only the HTTP API.

Direction is strict: `service → core`, `web → service API`. Core never imports a middleware client; service never reimplements domain logic.

## 3. Four access levels

Every source is kept verbatim and stays reachable at four levels over the same block sequence. These are parallel views, not fallbacks.

| Level | What | Store | When |
|---|---|---|---|
| L0 | verbatim blocks + structure map + block-aligned original media, fetched by locator | Postgres + private S3-compatible object storage | unconditional |
| L1 | lexical full-text over blocks | Meilisearch (index per user) | unconditional |
| L2 | semantic chunks | Qdrant (one collection, tenant filter injected in the adapter) | per IntakePlan |
| L3 | canonical knowledge compiled under the contract | canonical library (versioned; + derived projections) | per IntakePlan |

An `IntakePlan` is two knobs — `canonical_treatment` (full / distill / card / none) × `semantic_indexing` (full / summary / none) — proposed mechanically from the shape of the source, overridable by the user, and audited. The user-facing intake archetypes name processing intent, not genre — genres are an open set no list can close; an archetype is a named preset of the two knobs. Ingest itself is cheap and synchronous: an import writes L0 and enqueues `index` and `compile` jobs; everything expensive happens in the worker.

## 4. Authoritative vs derived

Only two things are authoritative: the L0 sources, and the canonical library. The canonical library is a **versioned, append-only history**: every compile appends a version, any past state can be snapshotted or rolled back, evolution is reviewed on its own branch, and every version is stamped with the hash of the contract that produced it. Everything else — L1/L2 indexes, L3 projections, glances, and whatever an index component indexes for itself — is derived and rebuildable from those two.

(The shipped implementation: L0 text, structure and media manifests live in Postgres, while immutable media bytes live in private S3-compatible storage (RustFS in the local stack) behind the `MediaStore` port. The canonical library is one Git repository per user, whose commit/tag/revert/branch map one-to-one onto the semantics above. These are adapters, not architectural commitments.)

Four consequences worth internalizing:

- Rebuilds are byte-deterministic even where an LLM was involved. Semantic chunking (the default `semantic` strategy; its boundary philosophy is inspired by [nemori](https://github.com/nemori-ai/nemori)) uses one structured LLM response to return each topic/episode's search-friendly title, factual third-person description, and block coordinates. The description preserves concrete participants, time, place, events, decisions, emotions, reasons, plans and outcomes that the covered blocks support; known source occurrence dates anchor relative-time normalization, and absent dates are never guessed. This generated representation is derived L2 content, not source: chunk text remains a verbatim slice addressed exactly like mechanical chunks. The v3 manifest records coordinates plus title/description and replays them on rebuild. A boundary-only older manifest is upgraded once by describing its **fixed** spans; a mechanical equality check refuses any attempted boundary change. An episode longer than `CHUNK_SIZE` is sentence-sub-split before embedding. Scripted/keyless models still fall back to mechanical sentence chunking. L2 stores two independently ranked representations: raw vectors embed source context plus labelled caption/OCR and the verbatim chunk, while one episode vector embeds source context plus the title/description and retains that dense description as derived payload. Every point resolves to its corresponding verbatim L0 span. Fast recall may surface high-ranked descriptions as a third, explicitly labelled **derived episode summary** context face, enriched mechanically with source title, occurrence time, section and exact block span; it never presents one as verbatim or canonical, and direct raw/claim evidence wins any exact-detail conflict. Retrieval fuses lexical, raw-vector and episode-vector rankings with ordinary RRF, then suppresses lower-ranked overlapping source spans without widening the winner or adding duplicate score. Better search meaning therefore never dilutes the raw vector or creates a second authority or citation space.

  Segments may also *overlap* (`SEMANTIC_OVERLAP`, factory default `smart`): the model returns closed block intervals, so a hinge — the sentence that closes one topic while opening the next — is indexed as part of both neighbouring segments, judged per boundary rather than as a fixed stride. Whether that is allowed to degenerate is not left to the prompt: five write-time gates (real ordered endpoints, strictly increasing starts, gapless cover, at most three shared blocks, no more segments than blocks) reject the whole output, and the window falls back to the zero-overlap partition. The duplication a hinge causes is purely derived — both chunks address the same source blocks (I4), and retrieval suppresses the lower-ranked overlapping result. `off` retains the zero-overlap geometry, but adding the episode representation intentionally creates a new prompt baseline; earlier boundary-only measurements are not presented as same-harness results for this version.
- Upgrades never rewrite the canonical layer. A new projection strategy, a new index, a new render, a newly enabled component — all rebuild derived artifacts; the canonical history stands.
- An index component's projection sits on the derived side with everything else, and the same two paths keep it there: the framework tells the component when one source finished indexing (its incremental write), and `rebuild_derived` tells it to re-derive its whole index from L0 and canonical. Nothing in the framework reads a component's projection as an authority, and a component holds no write path to the canonical store — enabling one adds structure over the library, disabling one takes the structure away and leaves the library exactly as it was (I7).
- The routine commit path syncs projections incrementally: the fresh snapshot is diffed against the last recorded projection manifest and only the delta lands in the indexes (only added or changed claims are re-embedded). The full rebuild (`scripts/ops/rebuild_derived.py`) is the explicit repair and migration path, not the daily one — and either way, the increment is a cost optimization, never a new source of truth.

## 5. Canonical write mechanics

**The unit is a claim.** A claim is a text block carrying an **anchor** (an HTML comment `<!-- c:xxxx -->` embedded in the markdown) and one or more **citations** written `[cite: <source-id> ¶a-b]`, where `¶a-b` is a block span in the cited source. Anchors are content-addressed and system-assigned — the model never mints one — and once assigned they are immutable.

**A document has two parts, and only one of them is a ledger.** The **ledger** is the body: anchored, cited claims, written one at a time, anchors immutable, deletion unavailable. The **overview** is a bounded head above it — the document's *current picture of its subject*, in four slots: `definition` (one sentence: what or who this is), `summary` (the state now), `introduction` (background, origin, why it matters) and `connections` (links to other subject pages, each with the relation in one line). Region and slots are delimited by HTML comments the system writes and the model never types (`<!-- overview -->`, one marker per slot), so reading a document never depends on which language pack wrote it.

**One citation language, images included.** An image does not invent a second one. It is attached to the message's ordinary block, so the same `source_id + ¶ span` resolves the verbatim text, original image bytes, digest, MIME type, and any explicitly labelled caption/OCR representation with its producer. The compile path can send caption/OCR only or real image content blocks according to the active compile model; native mode re-reads and verifies the stored bytes before the model call. A caption remains derived evidence and never impersonates direct image inspection.

**Four write verbs, and no fifth.** The compile model works against an in-memory patch draft, through write tools that are each bounded to one claim or to the head: `create_document` and `append_block` add a claim, `edit_claim` corrects one in place, `supersede_claim` records that a new claim is the current state of what an older one said, and `rewrite_overview` replaces the head whole. There is no whole-document write, so a claim cannot be dropped by transcription. Read tools (and any an enabled component contributes) complete the face.

Before a draft becomes a commit it must pass the **gate**: a mechanical check of anchor continuity and uniqueness, citation resolvability and shape, provenance on every new claim, the supersession links, the overview's own three checks, link-target existence, frontmatter completeness, path ownership under the contract's templates, the immutability of frozen archive volumes, and whatever an enabled index component adds over its own family (§6). Citation checks apply to what this round introduces — citations carried verbatim from earlier commits are grandfathered (they were verified when first written), so a forward compile is never rejected over a source it was not given; anchor uniqueness, by contrast, is checked repository-wide with no grandfathering. Violations trigger one repair round; if violations remain, the compile aborts and the canonical layer is untouched.

**Each round is bounded by its own tool-call budget, and the budget is stated rather than merely enforced.** The first round's default is derived from the material — `max(40, 3 x supplied sources)` — because a round must be able to read every source and append at least twice per source; a fixed 40 cut a 36-source day group mid-append on a real 88-day rebuild and cost 14 day groups (156 sources) their place in the library. A deployment that states `COMPILE_MAX_TOOL_CALLS` states the absolute number instead. The repair round is never handed what the first round left over: it gets a fresh allowance of its own, `max(12, 3 x violations)` capped by the same ceiling — one counter shared across both rounds meant a first round that spent everything left the repair round unable to run at all, so the gate wrote its feedback to a model that was never asked again and the compile aborted every time. Inside a round the budget is visible: when it drops to a low-water mark of six calls, one notice states the calls remaining and what the gate's own predicates — the overview a touched page owes, and every enabled component's checks — already find owed on the current draft, so the last calls are spent on what the gate will demand; and a round that ran out says so at the top of the feedback the next round reads, so the repair round does not start the exploration over.

**Why the one wholesale write is safe.** `rewrite_overview` replaces the whole region in one call — the four prose slots and the structured `fields` beside them, written whole through the same door `set_fields` uses — mints fresh system anchors for its blocks and leaves the ledger byte-for-byte. The overview is a SNAPSHOT, not a changelog: nothing in it only grows, which is the only reason a wrong entry is repairable at all. Every call is a judgement over the picture that already stands there, and the four outcomes are the call shape: keep it (do not call), merge or rewrite it (call with the whole new region), drop it (every slot empty and no fields — the region is removed and the document goes back to being its claims). That the previous picture was observed is mechanical rather than asked for: `rewrite_overview` and `set_fields` refuse a document this compile has not read. That is safe for one reason, and the gate is that reason rather than a hope: the overview may hold nothing the ledger does not already carry. Every block must reference a ledger claim (`c:xxxx`) or cite a source span, from anywhere in the library — an overview grounded on another overview grounds nothing — and the region is bounded in characters (`OVERVIEW_BUDGET_CHARS`, default 2000) so "the current picture" cannot grow into a second ledger nothing keeps in step with the first. The same region has a floor under it as well as a ceiling: a document this round TOUCHED whose ledger has passed `OVERVIEW_REQUIRED_AFTER_CLAIMS` claims (default 8) and still has no `definition` is refused — at `finish_compile` first and at the gate behind it — because a model maintains a head that exists and never starts one (on a real library 41 of 85 pages never got one, several of them holding 20–31 claims), and a page nobody can read the shape of is not honesty about how little is known. Pages the round never touched are not judged; they converge on their next touch. Those rules are enforced twice on purpose: the write tool refuses the call before a byte is written, naming every failing block at once, and the gate stays behind it as the final arbiter for a draft that reached it without passing a tool. A rule first heard at the gate costs a whole repair round; a rule heard at the tool face costs one call. `definition` is one short block because it is the line every glance and outline shows. Overview anchors are the single exemption from anchor continuity: they are retired by design on each rewrite, so losing one loses nothing. A reference the model dressed in the citation grammar (`[cite: c:xxxx]`) is reduced to the bare anchor at the write boundary rather than bounced back as a violation — the wrapper is the only thing wrong with it, and stripping a wrapper is a mechanism where a repair round would be a conversation. The whole rewrite is one `overview_rewritten` compile event naming the document — not N claims added and N vanished, which would be arithmetically true and materially false.

**Supersession separates *the world changed* from *I was wrong*.** `edit_claim` corrects a claim in place; `supersede_claim` records that a new claim is the **current state** of the fact an older claim stated — a role, an employer, a deadline. The old claim stays byte-for-byte and becomes frozen history; the new claim sits right after it with a system anchor and a second comment naming its predecessor (`<!-- supersedes: c:xxxx -->` — a separate marker, so the anchor grammar is untouched). The gate holds every link to the same shape: the predecessor exists, chains are linear and acyclic, a superseded claim's text never changes again, and the successor cites new evidence — "only new evidence may supersede a state" is a rejection, not a reminder. From the marker alone the framework derives a document's **current view** (claims with no successor), the **history** of one fact (its chain), and a `claim_superseded` compile event the brief narrates as a state change rather than an addition. Walking a chain by *date* — what held on a given day — needs a calendar, which canonical does not have; that is the `time` component's `as_of` (§6). Both verbs preserve the block's *form*: a claim that lived as a list item stays a list item, however the replacement text arrives, because the shape of a block is the document's structure and not the wording the write was about.

**Rollover** is maintenance, not judgement. Documents that grow past a size threshold are rolled over: older claims move byte-for-byte into frozen archive volumes (`<doc>/aNN.md`), the active document keeps a recent tail plus a machine-managed history card, and a dedicated gate asserts byte conservation and exact anchor survival across the move. The card is not the overview: the card indexes the archive, the overview reads the ledger, and a rolled-over document carries both.

An optional **coverage challenge** (off by default) audits each compile right after it lands: questions are generated blind — from the material and the contract, never from the compiled result — probed against the recorded claims, and judged with the material as ground truth. Confirmed gaps feed one compensation compile whose writes pass the same gate as any other; the audit points, the gate enforces.

## 6. The compile contract (skill)

A contract is registered as a `SkillVersion`: skill id, version, instructions (the judgement — what deserves to be recorded, at what granularity, under what wording), path templates (the directory skeleton of the library, and the sole basis of write permission), and contract rules. The whole thing is hashed; the hash is stamped into every canonical commit, so any library state is attributable to the exact contract text that produced it.

The framework extends in exactly two directions, and they extend different things.

**Schema packs extend the judgement.** They are additive contract fragments composed onto the base deterministically, per user — a pack can add families, never remove them. A pack is text, it changes what deserves to be recorded, and it is hashed into the same identity as the contract it extends.

**Index components extend the structure.** A component is business-specific *structure* over a contract family, contributed through one protocol (`components/`) at the framework's own seams: write-time checks at the gate — run by every channel that authors canonical, the daily compile, a whole-KB evolve and the adopt merge that lands one, because a field invariant belongs to canonical rather than to one writer — an extra line under the family's documents in the compile outline, read tools for the compile model, tools for deep recall, routed lookup paths for fast recall (§7), one mechanical line under a source in the compile task stating what the source boundary knows and the transcript cannot show, and a **projection channel** — the framework tells a component when a source finished indexing and, on an explicit `rebuild_derived`, that its whole index should be re-derived. A component may therefore keep a persisted projection of its own, derived and rebuildable like every other derived layer (I2, I7), and fail-soft: a component that raises may cost a stale projection, never a failed job. Core knows no component; like a contract, the application registers the ones it enables (`PNEUMA_KNOWLEDGE_COMPONENTS`), unknown names fail loudly at startup, and with none registered every seam renders exactly as it did before the concept existed. The enabled set is stamped into every canonical commit's trailer beside the contract and overlay hashes, so a commit states which contract, which wording and which components produced it.

The line a component may not cross is what makes the seam safe: **it holds structure and pointers — identities, edges, counts, spans, each resolving to a source span or a claim anchor — never prose knowledge.** It indexes; it does not know. Whatever it derives serves retrieval directly and reaches canonical only by riding an ordinary compile: the contract rules on what a component put in front of it, and the same gate judges the result. There is no promotion step, no second review model, and no second authority.

Two components ship as reference implementations. **`people`** gives person pages two machine-readable frontmatter fields — `identities` (`scheme:value`, at most one page per identity) and `aliases` (not somebody else's name: neither another person page's alias, title or slug, nor a display name the sources record for an identity this page does not hold) — both part of the overview and written whole with it, both facts the gate and the write face refuse mechanically, together with a third: **two person ids that both SPEAK in one conversation are two people**, so one page may not bind both (an IM `sender_id` and a meeting `speaker_id` are person ids; an email address is not — one human writing from two addresses is ordinary, and `email/v1` establishes no equivalence between them). All of them are judged over the pages a round TOUCHED — body or frontmatter differs from base, or the page is new — so one old wrong page cannot block every later compile while no write of one escapes them, and the whole rule set is `people.identity_shape`, `people.identity_duplicate`, `people.identity_cospeakers`, `people.alias_collision`, `people.alias_undecided` and `people.not_ready`, the last of which refuses a round whose library-wide mirror could not be loaded rather than judging it against an empty library. Beside them, a `find_person` lookup for the compiler, a `person` fast path, a `people_around(subject)` fast path and deep tool — the people the library links with a project, team or topic, derived from canonical's own links and carrying the linking claim as the evidence, for the question that names a subject and no person — and `enumerate_identities`, the closed set of external identities the sources record in a date range with the person page bound to each or `(unbound)`, so "everyone who…" is judged over a complete candidate list whose residue is visible rather than over search hits. It also keeps a persisted projection of **address terms** read off turn structure, decided by concentration rather than frequency. Because evidence a gate does not force is evidence a model skips, each term the library reports for a person this compile's sources carry must end the round either recorded in that page's `aliases` or declined (`decline_alias`) — and that question is asked ONCE. A decline stores nothing anywhere: canonical records what is known about a person, not the names that are not theirs. What closes the question is the page being written, judged on two derived dates the library already holds — the projection's `reported_since` (the day the pair crossed the reporting bar) against the day canonical last committed that page — so a page written since has been shown the question and is never asked again, whatever it decided. The framework makes the decision unavoidable and leaves what it is entirely to the contract. **`time`** keeps one derived row per L0 block — the block's UTC instant and the calendar day it falls on in the subject's timezone, with the zone and where that zone came from — and offers a `timespan` fast path, a `timeline` / `as_of` pair of deep tools, and a per-source time line in the compile task. Both are described in full, with the checklist for writing a third, in [design/index-components.md](design/index-components.md).

Every model-visible string in the framework lives in a **prompt catalog** and can be overridden at startup; the override set is hashed and stamped alongside the skill hash, giving each deployment a two-axis identity: *which contract, which wording*. The rendered system message is byte-stable: no timestamps, no task content — those travel in the human message. This is what makes provider prompt caching effective and compile behaviour attributable.

How to actually write a contract is a craft of its own: see [guides/compile-contract.md](guides/compile-contract.md).

## 7. Retrieval

Four lanes over the same library, increasing in cost:

- **rag** — L1 + L2 in parallel, fused by reciprocal rank; returns hits, no LLM.
- **fast** — one LLM call over assembled context: a glance of the library, L3 claims, derived L2 episode summaries, and L1/L2 verbatim windows.

The glance carries one level below each document's title: its overview `definition`, the same line the compile outline shows, so a lane deciding what to read can tell two similarly-named pages apart without opening either. A page with no definition falls back to its own current ledger on that line, labelled `ledger:` rather than `definition:` — when a page holds little, those few claims already are its overview; nothing is generated (the claims' own words, with machinery, markdown and superseded predecessors removed — one shared markdown-to-display-text reading, so a link keeps its label and loses its href), it stops on a WHOLE claim under the definition's own ceiling and never on a character, and a page whose first current claim will not fit under that ceiling simply gets no ledger line — a claim cut in half is a different claim, and this is a slot read as fact. The two labels stay distinct so "someone stated what this is" is never read as "this is what the page happens to hold".
- **deep** — a bounded agentic loop seeded with fast's evidence, with search/fetch/read tools and a forced conclusion when the budget runs out; returns its trail.
- **briefing** — a byte-stable evidence pack built once on a pinned snapshot, then asked many times.

L1 lexical hits, L2 raw/caption vectors and L2 episode-description vectors are three
independent rankings. Each path supplies twice the final cap so post-retrieval dedup can
backfill instead of shrinking recall. Ordinary equal-path RRF rewards agreement, while exact
lexical-only identifiers and dates can still outrank a broad episode-only match. The fused pool is then
deduplicated by rank-ordered overlap suppression on `source_id + block span`. An overlapping
raw/caption or lexical span always owns the citable result over an episode-only span; the
episode may raise its rank, but cannot replace its more precise evidence. Multiple
representations therefore improve rank without consuming duplicate answer-window slots or
chaining overlapping episodes into a mega-window. No retrieval path receives a fixed quota.
Fast then separates cheap breadth from expensive context: the product defaults retrieve up
to 80 claim candidates and 60 fused source-span candidates, while the final call receives at
most 40 claims, 16 explicitly derived episode summaries, and 6 verbatim windows. These are
corpus-agnostic operating values for an interactive personal/team knowledge base, not rules
about any particular corpus or question category. The summary face keeps the episode description's
information density; the smaller raw face keeps exact wording and direct verification.
The fast response echoes all admitted summaries as `used_episode_summaries`, with mechanical
`derived=true` and `verbatim=false` labels; the Recall UI renders the same metadata and links
each summary back to its exact L0 span.

Fast has an opt-in **quality composition** profile over those same parallel views. With
`evidence_strategy=select`, one structured recall-model call receives broad numbered
claim/episode/raw candidates plus the canonical glance and returns coordinates only. The
framework rejects invented coordinates, unions deterministic high-ranked anchors, enforces
the existing final caps, and follows selected claim and episode provenance back to bounded,
deduplicated L0 passages. This is ephemeral query composition, never a new authority.
`answer_format=structured` independently separates answer kind, clean answer text and
citations; only exact aliased spans present in the evidence are admitted. Either stage is
fail-soft with explicit degradation telemetry. The selector is serial between retrieval and
answering, so its latency and token cost are traced separately as
`recall.fast.evidence_select`; candidate counts and the model's pre-safety-head choice counts
make its actual contribution observable. Every answering response carries citation-free
`answer_text` beside the backward-compatible cited `answer`. A third strategy,
`evidence_strategy=all`, spends no selection call at all: the candidate pool `select` would
have judged is assembled in exactly the same faces, order and format and handed to ONE answer
call, so `used_*` reflect everything handed over, `model_selected_*` stay zero and the
`select` stage reports `skipped` — its only bound is a character ceiling on the assembled
context (`RECALL_ALL_CONTEXT_CHARS`), which drops windows, then episode summaries, then the
lowest-ranked claims and marks the answer `evidence_selection_degraded="all:truncated"`
rather than cutting silently; under `structured` its schema opens with one bounded
`deliberation` field so the review no selector performed happens inside the answering call,
returned on the wire and never in the SystemMessage (I5). The default `ranked + text` path
remains unchanged.

During context assembly, semantic raw/episode spans remain the natural units recorded at
ingest: they are not expanded a second time, and only genuinely overlapping spans coalesce by
default. A bare lexical-only block hit expands by just one following block by default;
bridging
disjoint nearby spans requires an explicit, domain-validated override.

Answering recall never includes original media merely because its model can consume it. The
query tool owns that cost/attention decision through the enum-list argument
`include_original_modalities` (empty by default; currently `image`). When `image` is selected,
fast and deep's seed evidence replay images attached to the selected L1/L2 body windows:
immutable L0 bytes are re-read and verified before becoming real image content blocks. When it
is omitted, fast keeps labelled caption/OCR representations in text form and no original media
bytes are read. Images outside the selected windows never enter the call, duplicate digests are
collapsed, and the volatile question remains the final human-message content block.

The fast lane's claim face carries two opt-in stages around its dual-path retrieval (both off by default; the off path is byte-identical). **Planning** (`RECALL_PLAN_QUERIES`): one small call derives extra keyword queries from a multi-aspect question, every query retrieves at full strength, and one RRF fusion pools the union — result-driven multi-round retrieval stays deep's job. **Reranking** (`RECALL_RERANK_MODEL`): a `Reranker` port (core) scores the pooled candidates against the original question and the best `RECALL_CLAIM_CAP` enter the prompt — rank-then-drop, with RRF kept only for dedup, backfill, and the failure fallback. Two providers ship: `llm` (the recall-role model pinned to reasoning effort `none`; input-heavy, output-tiny, no extra service) and an OpenRouter `/rerank` endpoint model name (dedicated cross-encoder, billed per search unit). Reranking is off by default because the ordinary lane already separates a wide candidate pool from a bounded final context; deployments turn it on only after same-harness measurement. Candidate pools are also deduplicated by text containment: an equal or contained claim statement is dropped for the more complete one, which keeps re-filed facts from burning budget slots.

An enabled index component (§6) may also offer **routed lookup paths** to the fast lane. The built-in paths are homogeneous ranked lists and fuse by RRF; a component path answers a structured query (`person(alias="…")`, `timespan(since, until)`) with exact results that carry no rank, so it is neither run blind nor fused. When at least one path is offered, fast spends one routing tool-call turn — the paths bound as tools, zero or more calls emitted in a single turn, never a loop — and runs the chosen paths concurrently with the built-in retrieval, which never waits for them. Their results form a fourth evidence face under their own header; every candidate is an ordinary claim anchor or source span (I4), so citation aliasing and the structured answer's admission check apply unchanged.

A path returns **everything it knows** — the whole page, the whole range — and the framework decides what is shown. First one deterministic, model-free ordering against the question: lexical overlap on unicode-aware tokens, a `current`/`superseded` term, time proximity, the path's own order as tie-break; a wired reranker replaces the overlap term and fails soft back to it. Then the path's declared cap spent on THAT order, under two floors — one window whenever the path returned any, and the top claim of every distinct section. Then a character budget over the whole face (`RECALL_COMPONENT_BUDGET_CHARS`), because item counts bound how many things a path contributes and not how large they are. Every truncation is described rather than counted: which sections, which days, and an over-long excerpt cut at a block boundary that names the blocks it left out. A cap spent on document order is how the one claim that answers the question ends up just past the edge, which is why ordering, truncation, dedup and budgeting are stated once in core and never inside a component — a component decides what it knows, never how much of it a prompt sees.

Dedup runs so that the ranked faces are never disturbed — they carry relevance order and the selector or reranker has already judged them — so the component face hides what they already show and says how many, and a ranked claim a lookup also returned is labelled `via:<path>`: corroboration without a second copy. Under `evidence_strategy=select` the component results join the numbered candidate pool as their own group instead of bypassing the selector, and what it picks renders inside the ordinary faces. The deep lane takes the opposite discipline — completeness over caps: its component tools paginate, every response ends with the exact call that fetches the rest, and `timeline` can return one day verbatim, block by block, so a day can be read rather than sampled. What the router chose, with which arguments, an argument it rejected as malformed, and any path that timed out are telemetry, not silence — they reach the HTTP answer and the Recall UI beside the evidence itself. With no path offered, or with `RECALL_COMPONENT_PATHS` off, there is no routing call and the lane is byte-identical to the lane without the seam.

Independently of any component, the claim face respects supersession (§5): a claim canonical has superseded is labelled `superseded` and placed after the live ones, judged at assembly over the lane's pinned documents, so an index that still matches the old words never presents history as the current state.

Because the lane is now several model calls around one concurrent gather, its cost is reported **per stage**: every stage — planning, the retrieval gather and each arm inside it (claims, windows, glance, one per routed component path), the routing turn, rerank, selection, evidence assembly, the answer call, and the total — carries its own measured wall-clock on the result itself, in one fixed order with the stages that did not run present and marked, so "which part was slow" is a property of the answer rather than of a log the owner cannot read. The deep lane reports the same way with the one difference its shape forces: an agentic run has no fixed vocabulary to emit against, so what it carries is the run's own sequence — each model turn, each tool call measured around the tool itself, a budget-forced finalize when there was one, and the total that wraps the loop — interleaved in the order it happened, because there the order *is* the finding. Each step reaches a waiting UI already carrying its duration, so a search that is still running is already legible. The briefing lane reports both of its halves the same way, in whichever of the two shapes the half has: a build is mechanical (retrieval, expansion, budgeted assembly, no model call anywhere), so it emits a fixed vocabulary complete — and is persisted with the pack, so a briefing built weeks ago can still say where its seconds went; an ask is the agentic loop again, and its total wraps the loop rather than the pack it asks over, because that pack was built once and reused since. And the retrieval lane — no model in it at all — reports in the same shape and the smallest vocabulary of the four: the query embedding, the two index lookups run one after the other, the fusion, the overlap merge, and the total; a search that finds nothing has still spent seconds somewhere, and a lane too cheap to explain is a claim to be checked rather than assumed. And the whole breakdown is **streamed as it happens**, not only reported afterwards: the same measure sites announce each stage when it begins and again when it settles, so a waiting reader watches the diagram grow — including the answer text as the model writes it — instead of staring at a spinner and being told where the seconds went once the waiting is over. One clock, so what is drawn live and what arrives with the answer cannot disagree. And beside each duration a stage carries a bounded **preview** of what it was handed and what came out — the queries a planning turn wrote, how many claims a face returned and the first few of their anchors, the lookup a routing turn chose and with which arguments, the characters each assembled section spent — because a duration says a stage was slow and never says what it was slow *at*. The bound is mechanical rather than advisory: every preview passes through one helper that caps the serialized object, elides strings and truncates lists, so a careless call site cannot turn telemetry into a second, unbounded way for source text to leave the library.

Plus **live context**: given an ongoing conversation, propose zero or one grounded suggestion card per tick — silence is the norm, not a failure. Nobody asked a question here, which inverts the whole shape: the lane cannot spend retrieval first and decide afterwards, because most of what a room says is not worth a lookup. So a full-scope tick is **three stages**. **Discover** is one small reasoning call at low effort, and it has one job stated as a principle rather than as a list of cases: **write, on the room's behalf, the one question most worth asking right now**. It reads the pending window — everything said since the last tick, not a fixed tail — plus the cards already surfaced and the session's subject ledger, and answers either `skip(reason)` (no question worth asking can be written: small talk, already mined, nothing new) or that question as the *intent*, a one-or-two entry *plan* for going and answering it, and a *worth* score for what the answer would be worth to the room. Every rule the lane accreted case by case falls out of the one principle: an unnamed role means the room would ask *who is that*, a first-mention product means *what is X*, a find-a-person ask means *who here knows X best*, and a subject named over and over that nobody asks about is a question the room already knows the answer to. The `intent` doubles as the delivered card's trigger line, which is why it is phrased as a question somebody could have asked aloud — the owner reads it as the reason the card appeared. A skip ends the tick having touched no index at all; a `worth` under the floor is the same thing decided on price. **Retrieve** runs every plan entry concurrently — registered component paths (§6) through the ordinary routed-path machinery, `semantic` as one claim + window retrieval on the intent rather than one per turn — and turns what comes back into numbered candidate cards **mechanically**: claim text verbatim, citations attached by construction, no model in the loop. **Pick** is one weak fast call with reasoning off, and it applies exactly one criterion: does this candidate's own text ANSWER discover's question? It chooses the candidate that does or none, writes a short lede answering that question in the room's own language, prunes the candidate's own citations by index, and scores how directly the text answers it. It never rewrites — the delivered card is that lede over the candidate's evidence byte for byte, so the framing is a guess and the substance is the library's own words, and the reader can see which is which.

One number gates twice: `min_confidence` is discover's `worth` floor (below it, nothing is retrieved) and pick's `confidence` floor (below it, nothing is delivered) — a deployment that wants fewer interruptions wants fewer of both. Repetition is handled by a **subject ledger**, per conversation and model-free: it counts what retrieval touched and what was delivered about it, feeds a digest into the discover turn (so a subject the room keeps naming without asking about is visibly common ground), and mechanically refuses a second *introduction* of a subject however convincing the two calls were — while a *fact* about that same subject is a different card and passes. Briefing scope is untouched by all of it: its evidence is a pack frozen at build time, so there is nothing to plan, nothing to retrieve and nothing to choose between, and it stays the single round with its four gates. Two deliveries of the same conversation: a one-shot evaluation over a posted window, and a long-lived socket that holds the pending run, the quiet period, the in-connection dedup and the ledger server-side.

The discover call reads its window in **two parts**, and the split is the difference between what a tick MINES and what it UNDERSTANDS. The pending run keeps its consumption semantics exactly — a tick processes it, delivered or skipped, and the next one starts from what came after — but above it now rides a bounded, read-only tail of turns earlier ticks already processed, under its own heading and with the contract forbidding it to be mined. Without it, intent formation saw only what was new: four turns about Apple's foldable phone were consumed by a quiet skip tick, and the fifth turn alone produced an intent about *Android* foldables. The subject had not changed; the window had.

How eagerly the lane digs is a **density** posture — `eager` | `balanced` | `quiet` — and it is a real policy field rather than a name for three thresholds, because thresholds only move how MUCH gets through and never WHAT is looked for: on the eager preset the single turn 「建议这个事情还是交给我们日本市场的负责人来做吧。」 was skipped outright, since a role standing in for a person nobody named was not a gap the one shared wording recognised, whatever the floors were set to. It varies exactly one clause of the discover contract — **how latent the question may be**: under `quiet` only a question somebody actually asked aloud counts, under `balanced` one the conversation clearly implies, and under `eager` also one the room does not yet realise it should ask (an unfamiliar term nobody stopped to explain, a role standing in for a person nobody named), composing with rather than overriding the common-ground and already-mined rules. The skip vocabulary and the three output fields stay shared, so these are three wordings of one contract, byte-pinned per (component set × web × density). The pick contract does not vary: how honestly a card is delivered is not a density matter.

A **glance short-circuit** sits between discover and retrieve, and costs no model call. Where a plan names a subject the library holds, the library already holds one grounded sentence about it — the overview `definition`, written by a compile, rewritten whenever the picture changes, and resting on ledger anchors whose claims carry its citations. That sentence is delivered immediately, verbatim, marked *provisional*, while stages 2 and 3 keep running; when the tick settles, the full card either upgrades it in place (same subject, same slot, the queue does not grow), settles it and queues beside it (a different subject), or simply clears the mark (nothing else came). It passes the same repetition rules and the same uncited refusal as any other card, a tie resolves to nothing rather than to one of them, and a skip never reaches it — the canonical read is awaited only once a real plan exists, so the tick that is this lane's steady state still touches nothing.

Beside the library, optionally, there is a **supplementary internet face** — off by default, and opened only where the deployment and the individual connection have *both* said yes, so the discover contract advertises a `web` lookup exactly when something can serve one (two byte-stable shapes of that SystemMessage, both pinned; I5 is untouched because the toggle never reaches the Human turn). It is reached two ways and they are counted apart: **planned**, when discover asks for it and the search runs concurrently with the library faces, and **fallback**, when discover did not ask but the library came back with an empty candidate pool — the one sequential case, and sequential because it is a consequence, since nothing was worth paying a per-search fee for until the library's silence was established. Either way the result is **candidate N in the same numbered pool**, chosen or not by the same pick call, with its pool stated on its face (`library` / `web`) and the contract ranking by match rather than by pool: an internal card that merely brushes the intent loses to a web card that answers it, and the reverse holds equally. Its provenance is a second citation shape — page title and URL — kept deliberately apart from `Citation`, because a URL is not an address in the one scheme (I4) and a `Citation` carrying one would resolve to nothing and quietly falsify "all knowledge links back to a source block". The library's citation gate therefore does not apply to it; what does is a gate at construction: an answer that named no page never becomes a card. The face is bounded at 15 seconds and fails soft — a dead search is a degraded row in the tick record and never a lost card — and its searches and cost ride that record, because a supplementary path that bills per query has to be legible.

Everything resolves through one addressing scheme — `source_id + block span` — so a lexical hit, a semantic chunk, a claim citation, a verbatim fetch, and block-aligned media all point into the same block sequence. Answers cite via query-local handles (`s01`, `s02`…) that never leak across one evaluation. Retrieval can be pinned to a snapshot — either a past version (read-only browse) or a frozen copy of the whole tenant — and a pinned query never silently falls back to live data.

## 8. Evolution

The evolution loop, end to end:

1. Compile events accumulate (what was added, revised, where).
2. A trigger fires — thresholds of new documents and claims since the last look, or a manual request.
3. The framework drafts a proposal: revised families, path templates, page restructuring — and rebuilds the library accordingly on an `evolve/<task-id>` branch.
4. A human reviews the diff: rationale, changed files, and any anchors that would be dropped, surfaced explicitly.
5. Adopt merges via a three-way, LLM-free reconciliation and rebuilds derived layers; drop deletes the branch. Drafts expire on a TTL.

Claims are never rewritten by evolution; what evolves is the model — the contract, the families, the shape of the library.

## 9. Invariants

Seven guarantees that hold everywhere in the code — safe to build on, and they take precedence over any local trade-off when changing the framework. Each names the mechanism that holds it; an invariant nothing enforces is an aspiration, and this list holds none.

1. **User isolation everywhere.** `user_id` is the first parameter of every port method; each user gets their own canonical library and lexical indexes; the vector store's tenant filter is injected inside the adapter with no unfiltered public path.
2. **Canonical and derived are distinct types.** Strategy or render upgrades rebuild derived artifacts only.
3. **L0/L1 reachability is unconditional**, regardless of what the IntakePlan decides about L2/L3.
4. **One addressing scheme.** All knowledge links back via `source_id + block span`; one citation syntax with one shared parser. Block-aligned media resolves through that address rather than through an uncited side channel.
5. **The system message is byte-stable.** Volatile content travels in the human message.
6. **Evaluation never leaks into the system it evaluates.** Answers, rubrics and expected-evidence fields belong to the eval package, and the package direction is one-way: `eval → core`, with neither core nor service importing it. A compile or recall input cannot reach a truth file because no import path exists.
7. **A component's projection is derived, and a component never writes canonical.** Whatever an index component indexes is rebuilt by the same `rebuild_derived` as every other derived layer; the canonical face it is handed at registration is read-only (`CanonicalReadOnly`), so its knowledge reaches the library only by riding an ordinary compile, under the contract and the gate.

## 10. Process topology

Four middleware containers (Postgres, Qdrant, Meilisearch, RustFS) plus two stateless processes:

- **API** (FastAPI / uvicorn) — ingest, retrieval, review surfaces; also serves SSE streams and the live-context WebSocket.
- **Worker** — drains the job queue per user, strictly serially (`FOR UPDATE SKIP LOCKED`; one in-flight job per user doubles as the single-writer guarantee for the canonical store). Six job kinds, unchanged by the component seam: `compile`, `index`, `challenge`, `evolve`, `evolve_adopt`, `groom`. A component is not a job — it rides the two that exist: the index job tells every enabled component that a source finished indexing, and a compile job opens with `prepare`, the one call that lets a component's synchronous seams read a projection written in another process. On restart the worker re-queues orphaned jobs; any exception completes the job as failed rather than leaving it claimed, and one model call that hangs is bounded by `COMPILE_CALL_TIMEOUT` so a dead connection cannot hold a worker until the next restart.

The Git binary is a runtime requirement (the canonical adapter shells out). Async discipline is full-stack: ports and everything touching them are `async`; pure helpers stay sync; unavoidably blocking work (git subprocess, chunking) is wrapped in threads inside adapters.

Model wiring is role-based — compile, recall, answer, deep, skill, evolve, challenge, live-context — each independently configurable, with a single one-hop fallback and a shared default. `recall` owns retrieval planning/glance while `answer` owns only the final fast-answer generation, so quality-first reasoning never taxes every retrieval helper. A `scripted:` model spec replays recorded responses for keyless, deterministic runs; embeddings accept a deterministic `fake:<dim>` for the same purpose. Tracing (Langfuse) is a no-op unless fully configured.

## 11. The engine directory

Everything that IS a deployment's engine — strategy, the compile contract, prompt overlays, the owner profile — can live in one directory, versioned as its own git repository, separate from data, secrets and machinery. `PNEUMA_KNOWLEDGE_ENGINE_DIR` points at it; unset (the default) means the deployment has none and every strategy key resolves exactly as it did before the concept existed.

```
engine/                    # its own git repo; one commit per apply
  engine.yaml              # model roles · compile image delivery · compile call timeout ·
                           # overview budget · enabled index components + the people family
  intake/intake.yaml       # chunk_strategy, semantic_overlap
  compile/contract.md      # the constitution — a DOCUMENT, never decomposed into knobs
  compile/challenge.yaml   # coverage-challenge knobs
  evolve/evolve.yaml       # evolve trigger knobs
  recall/recall.yaml       # answer style, retrieval budgets, the component face's budget
                           # and whether fast routes to component paths at all
  persona/profile.yaml     # the owner profile
  prompts/overlays.yaml    # prompt language + catalog key → replacement clause
                           # (the prompt extension point)
```

Three properties make it a mechanism rather than a convention:

- **Precedence is fixed at three levels: process env > engine file > framework default.** Explicit environment wins so operators can apply a temporary process-local override without dirtying the versioned unit; the engine file is the durable truth a person edits. It is enforced at settings assembly — the engine file's values are handed to `Settings` only for keys the environment leaves unstated.
- **Secrets and infrastructure never enter it.** Connection targets, ports and API keys stay in the deployment's environment; every write refuses a dotfile path and API-key-shaped content.
- **The picture is derived, never drawn.** A machine-readable engine schema (stages, knobs with their defaults and env names, apply semantics, pipeline edges) is generated from `Settings` metadata plus a hand-authored stage map, and a test pins the two in sync — adding a strategy knob without covering it fails the suite.

Each edit states its blast radius, which is invariant I2 made visible: `hot` (the next process to read the files picks it up), `restart` (API/worker rewiring), `future_compiles` (governs future compiles only; canonical is never rewritten), `derived_rebuild` (takes full effect for existing content after `rebuild_derived`). The contract stays a document with version history and an editor, never a form of toggles: knowledge modelling is judgement, and pretending it is checkbox configuration would be the one lie this framework cannot afford. Full design: [docs/design/engine-console.md](design/engine-console.md).
