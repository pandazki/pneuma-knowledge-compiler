# 全项目看板草图：未验证

上午一度想把入口改成“所有项目—全部任务—负责人—进度”，再从任务旁挂回变更片段。起因不是新访谈，而是我觉得三张孤立卡看起来太薄。这张图没有用户走过，也没有数据证明一个总览能回答陈放昨天纠正的关系问题。

| 草图区域 | 我想象的用途 | 贾宁指出的扩张 |
| --- | --- | --- |
| 项目总表 | 一眼看所有工作 | 先要求一套并不存在的项目结构 |
| 任务泳道 | 把沟通变成待办 | 把“说过什么”提前改写为“应该做什么” |
| 人员负载 | 找到负责人 | 未回答谁只是说话、谁能够作出判断 |
| 周视图 | 自动汇总进展 | 又绕回尚未证实有用的概览 |
| 变更卡入口 | 从任务进入来源 | 依赖前三块才能存在，无法单独验证 |

> 贾宁 11:16 的原话记录：“你连一条变化为什么要留、留到哪里都还没说清，就先做所有项目的任务板，等于把四个未知一起铺开。这个草图可以留，不能拿它冒充范围。”

我第一反应是看板以后总会需要，先搭骨架不算扩张。贾宁反问：如果明天只能让对方判断一件事，看板中的哪一列有独立证据？我答不出来。到午饭时只把页面移回草图区，没有删除，也没有继续做交互；它仍是我的偏好，不是已经验证的方向。

- 会前要问：对方遇到争议时，第一步必须看见什么？
- 会前要问：哪一项不出现，也不妨碍验证原句与后续判断的关系？
- 会前要写：全项目看板没有进入承诺，只是被质疑的备选草图。
- 尚未回答：试验对象、参与角色、数据怎么访问，以及谁能够确认关系变化。

今天没有落定一份正式边界。贾宁明确反对把看板扩张当默认路径，但“只留下哪一件事”要等明天继续谈；当前页面也未对外发送。
