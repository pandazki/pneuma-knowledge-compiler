# Knowledge route atlas surface brief

- Scope/mode: whole React surface; Operate with a guided Read layer for first-time open-source visitors.
- Audience/job: an OPC AI-native developer should understand the architecture in one viewport, replay the synthetic demo, then inspect one source-to-canonical-to-Git journey without learning eleven admin screens first.
- Direction: **Knowledge Transit Atlas**. Authoritative and rebuildable layers are colored routes; source, index, compile, canonical, and Git are stations and interchanges. The interface refuses the category-standard dashboard grid and exposes forms only inside task-specific station sheets.
- Selected composition: `.impeccable/mocks/transit-open-source-stage.png`, carrying the route-detail clarity of `.impeccable/mocks/transit-route-overview.png`. It wins because the architecture itself becomes the first-viewport artifact and each experiment begins at a named station rather than a generic form page.
- Memorable moment: selecting an Atlas source lights one continuous route through retrieval and compile gates, then opens a provenance sheet containing the exact source span, canonical claim, and Git commit.
- Themes: light = porcelain wayfinding mural under daylight; dark = midnight enamel transit control room. Route identities and station states remain semantically stable.
- Constraint: preserve the Pneuma mark and recognizable grouped navigation; all bundled content stays visibly synthetic; no private business/device assumptions, KPI theatre, checkerboard texture, dense hairline grids, or bento dashboard.

## Open-source demo journey

1. **System map:** understand authority, rebuildability, stores, and compile boundaries.
2. **Replay demo:** restore the deterministic OPC dataset and watch the active route.
3. **Run an experiment:** import a material, run recall, or evaluate a context cue from a station sheet.
4. **Verify provenance:** trace one answer or claim back to source and forward to Git history.
5. **Explore internals:** branch into sources, indexes, canonical documents, graph, history, and strategy evolution only when needed.

## Composition inventory

| Ingredient | Implementation |
|---|---|
| Architecture transit mural | Semantic HTML plus responsive inline SVG route lines and station markers |
| Grouped navigation rail | Existing React navigation, visually simplified and regrouped around Demo / Inspect / Internals |
| Route actions | Large semantic station buttons embedded into the system map |
| Experiment station sheet | React route host that presents existing forms as spacious task drawers, not permanent panel grids |
| Active provenance route | Existing dataset, source, claim, patch and snapshot data rendered into one continuous route |
| Layer legend | HTML legend distinguishing authoritative solid lines from rebuildable dashed lines |
| Synthetic disclosure | Persistent semantic status in desktop and mobile navigation |
| Day/night worlds | CSS custom properties; porcelain light surface and midnight enamel dark surface |

The comps are north stars, not screenshots. Generated English filler, fake counts, decorative store logos, oversized empty routes, and conventional upload dropzones must not be copied. Core text, controls, provenance, keyboard behavior and responsive layout remain semantic code.
