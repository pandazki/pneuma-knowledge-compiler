# 语音通话——前面一把嗓子，后面一座知识库

[English](voice-call.md) | **简体中文**

## 1. 为什么，以及一通电话不是什么

进这座库的其他每条路都是一个回合：你打字，它回答，你读。通话不是这样。知识主体正在走路、开车，或者端着一杯咖啡，想问库里的事——像问一个坐在对面的同事那样问：打断它，名字说到一半改口，说一句「不对，第二个」，而对方听懂了。

这和控制台解决的是不同的工程问题，差别不在麦克风，而在于**没有人在读**。一个写出来的答案花十一秒没关系，人看着阶段一格格走过，知道机器在干活。电话线上沉默十一秒，那叫掉线。这份设计里所有看起来不寻常的地方，都是这条约束一层层压下来的结果。

由此引出三件事，它们就是整份设计：

- 对话与知识是**两个模型的两份活**。主持一场全双工对话——边听边说，每秒做许多次「要不要开口、要不要让、要不要等」的判断——是语音模型的本行。它对这座库一无所知，也绝不该装作知道（§2）。
- 库说的话来自**平常的 fast 车道**，走同一份契约、同一道引用闸门、同一套归档范围，和其他任何一个答案一样——只是换了一个为「有人在静静等着」而生的姿态（§6）。
- 语音说出口而并非来自库的部分，在旁边的屏幕上**被标成这样**（§7）。语音是一种有说服力的媒介，而这座库的全部主张就是它不捏造；一通把两者混在一起的电话，花掉的正是这份主张。

**通话不是一条新的检索车道。** 它从 fast 召回取答案，什么也不写。跟它说话，不会改动这座库。

## 2. 分工：一把主持对话的嗓子，一座作答的知识库

语音模型跑在 OpenAI，用本部署自己的 `OPENAI_API_KEY` 连接。它带着一份很短的常驻提示词——它的谈吐、它的附和与打断策略，以及一段说明后端能帮上什么忙的话——不带任何库内容。供应商自己的指南就在强调这份提示词要小，而实测同意这一点：第一版把每种格式情形都写明白，结果把模型说出第一个字的时间拖慢了好几秒。

当语音判断需要这座库时，它**委托**。委托有两种模式，本设计用**客户端委托**——由我们自己的进程作答，而不是由供应商那边再叫一个模型。理由是引用闸门。托管的后端会自己从对话里组装上下文并据此作答；而这座库「不捏造」的主张，立足于证据是在**这里**被检索、被引用、被闸门把关的。一个从别处作答的通话，会是第二张不受闸门约束、却以这座库的名义说话的嘴。

由此带来一个值得直说的特点，因为后面每一节都被它塑形：

> **委托事件不带问题。** 它只说语音*需要*帮忙，以及在会话时间线上的*什么时候*。不说关于什么。

问题在转写里，把它还原出来是委托要做的第一件事（§6.1）。

## 3. 一通电话的形状

音频从不经过这个引擎。浏览器与供应商之间直接持有一条 WebRTC 连接，引擎只在开头上场一次，用项目密钥把浏览器的 SDP offer 换成一份 answer。这是该 API 记载的浏览器路径，而且有一个值得要的性质：**浏览器从不持有凭据**，它拿到的是一份 SDP answer 和两个 id。

随后引擎挂上一条 **sideband**——通往同一个会话的第二条连接，走事件与命令，音频仍留在 WebRTC 上——从那里起，凡是这座库有份的事都归它。

```
     ┌──────────┐      音频（WebRTC）      ┌────────────┐
     │  浏览器  │◄────────────────────────►│  语音模型  │
     │          │   字幕（data channel）   │            │
     └────┬─────┘                          └─────┬──────┘
          │ SDP offer                            │ sideband：转写、委托、
          │ ─────────────►┌────────┐◄────────────┘ 交付、用量、关闭
          │ ◄──── answer  │  引擎  │
          │   通话帧      │        │──► 问题成形 ──► fast 召回 ──► 可念的分块
          └──────────────►└────────┘
```

**每个动作只有一个主人。** 浏览器画字幕，可以挂断和静音。其余的一切——读转写、应答一次委托、把话交给语音——都是引擎的，而且只做一次。这不是请页面自觉遵守的约定：创建会话时数据通道被收窄到三条命令（关闭、静音、取消静音），所以页面若想给语音追加一条指令，会被供应商当场拒绝（`event_not_allowed`，已对着线上 API 验证）。

## 4. 三道门

| 门 | 是什么 |
|---|---|
| `GET /v1/users/{uid}/call` | 这里能不能打电话；不能的话，缺的是哪一样（`no_openai_key`、`no_recall_model`）。控制台据此画它的按钮；旧引擎回 404，控制台就什么也不显示 |
| `POST /v1/users/{uid}/call` | 进去的是浏览器的 SDP offer，出来的是供应商的 SDP answer 和两个 id。项目密钥只在这里用，别处都不用。创建会话是计费的，所以这道门只由一次点击抵达 |
| `WS /v1/users/{uid}/call/{call_id}` | 引擎知道而浏览器自己的数据通道不知道的那些：每次委托的卡片如何展开、用量、关闭。`{"type":"end"}` 挂断 |

一位知识主体同时只有一通电话。第二次 `POST` 会结束前一通——因为前一通还开着的通常原因，是某个标签页在通话中途死了，而那个会话还在计费。

## 5. 一通电话要守的规矩

这四条是靠实测才定对的，它们住在 `call/session.py`。

**最新的问题说了算；屏幕留下每一个答案。** 一次口头打断在供应商那边不取消任何东西——已经跑起来的活该怎么办，是本应用的决定。这个决定是机械的：新委托一到，所有还在飞的旧委托被标为*已被取代*。它们照样把检索做完、把屏幕上的卡片补全，但一个字也不交给语音。知识主体听到的是刚刚问的那个问题的答案，而片刻前问的那个，仍然在那里可以读。

**收到确认不等于说了出去。** 供应商在它估计文本已进入模型上下文时发确认——不是在有人听见时。所以确认从不被渲染成「已说」。从它那里取用的是它在会话时间线上的区间，正是这个区间让控制台能对上哪几句话立在哪个答案上，并标出那些谁也不立的（§7）。

**委托在任何工作开始之前先被认领**，所以一个重复投递的事件不会把同一次检索跑两遍。

**沉默也计费。** 会话只要开着就按分钟收钱，不管有没有人说话；把麦克风静音并不会让计价表停下。所以一通电话若连续 `CALL_IDLE_SECONDS` 没听到知识主体出声，就由引擎挂断；任何电话都活不过 `CALL_MAX_SECONDS`；而一通浏览器始终没开套接字、或套接字已经走掉的电话，按「无人认领」关掉。

## 6. 委托：被问到时，这座库做什么

### 6.1 问题成形

委托事件不带文字（§2），所以问题得从这通电话听到的内容里写出来。一次小的结构化调用做这件事：读转写的末段、本次通话此前问过的问题，以及一份这座库自己的页面标题清单。它产出一个独立成立的问题——把「第二个」对着前文解析清楚、采用知识主体最新的更正、修好听错的项目名——或者说转写还不足以确定，并给语音一句该问的澄清问句。

它向知识主体自己的原话失败。超时、供应商出错、模型不支持结构化输出、或者根本没有模型，都退化成「语音上次说完话之后知识主体说的那些」。那是个比成形后更差的问题，但它是知识主体的；一个因为辅助调用失败就沉默的委托，会让一把被要求不许猜的嗓子无话可说。

有两处细节，各自来自一通出过问题的电话：

- **标题清单按听到的内容排序。** 一座库迟早会超出任何固定的标题预算，而按路径顺序去截，被截掉的十有八九正是被问到的那一页。听错的名字通常还留着它大部分的词，那就让这些词来决定显示谁。
- **投机检索。** 把问题写出来要花一次模型调用——一次检索里最大的一段等待——而对于一个用完整句子问出的首问，它返回的就是知识主体的原话加一个问号。于是那些原话**立刻**发往知识库，与可能取代它们的那次调用并行，拿回来的东西被**扣住**：在成形后的问题被证明就是同一个之前，什么也不会到达语音。一旦不同——追问、更正、修好的名字——投机的那次就被无声丢弃，真正的检索再开始。白跑的那一次是实打实的成本，这份设计认这笔账。

### 6.2 fast 车道，换上说话的姿态

答案出自 `fast_recall`——控制台的检索视图和 `pkc recall` 调用的同一个函数，由同一段代码组装，所以一通电话所依据的证据面、归档范围与引用纪律，和其他任何一个答案分毫不差。不同的是一个姿态，而它的每一行都是用真实知识库上的实测换来的：

| 姿态 | 为什么 |
|---|---|
| `call` 模型角色，推理钉死为关闭 | 问题成形、选路那一轮和作答，全都发生在有人静静等着的时候 |
| 小的证据头部（10 条 claim、3 个窗口、2 条 episode 摘要） | 作答调用的提示词是第二大的一段等待，而一个说出口的答案只有三句话 |
| 提示词里不渲染概览 | 它占了那份提示词的三分之二，而它的挑选是检索里最长的那根杆 |
| `spoken` 回答风格 | 为「说出来」而写：先给结论，两三句平实的话，不用标题、列表或代码格式 |

这些加在一起，把答案的第一个 token 从大约十秒压到大约两秒。

`spoken` 风格短是有意的，而且同样是实测出来的：第一版有它三倍长——每种格式情形都写明白、数字要「按嘴上的说法写」——在同样的证据上把作答模型的第一个 token 拖慢了二到六秒。它不再说的那些，改由机制去做：交给语音之前，引用标记和 markdown 会被摘掉，因为屏幕上带着它们，而一把嗓子会把 `[cite: s3 ¶4-9]` 原样念出来。

### 6.3 一段时间不等于一个主题

有一次失败值得完整记下来，因为它产出了一个关于错误对象的、语气笃定的答案。被问到某个项目这两天进展如何时，时间组件返回了这两天的全部内容——好几千字，关于别的项目——而作答模型面对一片汪洋、又被要求只说三句话，就把这片汪洋概括了。它说了这两天发生了什么，而那不是被问的；它在第二段里补了一句「这些都不是关于那个项目的」，而语音根本没念到那里。

修法是给范围查询加一层主体范围：本来就在读问题的选路模型点出主体；范围本身的判定是机械的——不用模型、不做排序，一次包含判断——而当这段时间里没有任何内容提到这个主体时，查询返回空，这是诚实的答案，也是作答模型立得住的答案。匹配故意从严：第一版允许长名字命中其中两个词，结果把关于某个项目的问题，圈到了它兄弟项目的记录上——同一族的项目共享开头那几个词。漏掉一次宽松的提及，代价是一段摘录；放进一个兄弟项目，代价是整个答案。

### 6.4 交付什么，什么时候交

作答模型的 token 流会变成几次可念的交付，而不是一次。第一次在第一个分句边界就放出去，因为一个被要求写三句话的作答模型，常常写成很长的一句，而知识主体不该等它那个句号；后面的分块会合并，因为每一次交付都是语音可能重新组织措辞的地方。引用的方括号还没闭合时，一句话绝不会被放出去。

一道硬上限约束一个答案最多能说多少——大约二十五秒的话。风格那段是请求，这道上限是执行。屏幕上的卡片留着完整答案，知识主体想听剩下的可以接着问。

**不放安静上下文。** 供应商提供了一条通道，用来放「语音该记住但先别说」的内容。对着真实模型实测：凡是和结果一起放进去的东西都被说了出来——连标签一起念——而一把记着半截细节的嗓子，会凭自己的想象回答追问，而不是再查一次。委托只交付要说的话，别的什么也不交；追问就是一次新的提问。

## 7. 知识主体看到什么

通话界面分两栏。左边是双方的实时字幕，按会话时间线分组，且可被改组——供应商不给出任何回合边界，所以一行只是显示上的分组，从不是「某人说完了」的断言。右边是每次提问一张卡片：库理解到的问题、它处在什么状态，以及做完之后，用检索视图渲染答案的同一套组件渲染出来的答案，连同它的引用。

两栏之间跑着这个功能的诚实机制。每一行语音说的话，都按会话时间线上的区间，对上它所立足的那次交付——取该行开始之时或之前最近的那一次——并带上那张卡片的编号。**对不上任何一次交付的语音行，被标为「未查库」。** 那是语音自己在说话，而恰恰是这类内容，在所有界面里，数通话最容易被误认成知识。

很短的未链接行被豁免，而这条豁免是要点，不是妥协。「嗯」「我查一下」「好的」是语音在干它的本职，若每一句都标，这个标记出现得太频繁，读者就会学会跳过它——而这恰恰是这套机制唯一输不起的失败方式。阈值取长度，因为区分「一声应承」和「一句断言」的正是长度。

## 8. 成本

语音按会话开着的分钟数计费，有没有人说话都一样；后端是我们自己的，成本就是一次 fast 召回的成本。创建会话有一笔固定的开场费，哪怕没人说话也照收，所以没有任何东西会在页面加载时就创建会话。引擎那两道上限（§5）正是为此而设，别无他因；界面在通话期间显示实时花费。

## 9. 怎么度量

延迟**从委托事件量到交给语音的第一个字**，而且每张卡片带着自己的分解——转写稳定、问题写好、检索完成、第一批话出去——这样一通慢的电话是可以读出来的，不用猜。语音会用自己那句「我查一下」把等待盖住，这正是分工的意义所在；但这个数字不许躲在它后面：更早的一声应承，不等于更早的一个答案。

有两样东西是刻意分开度量的。**说出口的**是知识主体听到的；**卡片**是这座库说的。两者不同——语音会转述——而任何关于答案质量的主张，说的都是卡片。

## 10. 边界，以及这里没做的

- **通话什么也不写。** 不编译、不起草稿、不留所有者陈述。转写不会作为来源入库；一通电话若要变成 `owner-dialogue/v1` 材料，形状已经想过但没有做，而且它得面对一份要求「每轮非空、时间不倒退」的契约——被打断得很厉害的语音，不做处理是给不出这两样的。
- **一位知识主体同时一通电话**，而且只在它的界面开着时存活。
- **不做电话网。** 供应商支持 SIP；一座会接电话的知识库是另一个产品，有另一套身份认证。
- **托盘**还没有通话入口，目前只有控制台这一个。
- **它不是管家。** 这是检索车道前面加了一把嗓子。和编译这座库的编码代理对话，仍然留在管家视图的文字会话里，因为那里的单位是一个带命令和结果的回合，不是一句话。
