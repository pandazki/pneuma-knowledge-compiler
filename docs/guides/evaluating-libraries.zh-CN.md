# 独立评估知识库

[English](evaluating-libraries.md) | **简体中文**

用户明确要求评测时使用这份协议；普通建库不需要先完成评测。来源完整性、知识忠实度、
实际可用性和运行成本分别报告。

1. 构建前冻结框架版本、纯原料输入哈希、契约、模型和供应商、embedding、召回设置、
   提问时间策略及重试上限。新目录也必须使用新的正本、索引、租户和中间件命名空间。
   复用旧知识库不属于重新编译。
2. 编译只读取原始材料。评测题目、预期答案、证据标签、判分标准、旧预测和错题分析
   不得进入构建，也不得交给编写契约的 agent。宣称独立构建时，应使用全新的 agent 上下文。
3. 先冻结完成的知识库和构建记录，再释放题目。回答阶段只提供题目正文与标识，不提供
   预期答案或 gold evidence。回答时保持知识库不变，新增咨询记录单独记录。
4. 冻结全部预测、核对唯一标识与完整覆盖后再判分。原样运行指定评测器，保留准确命令、
   版本和输出。
5. 失败尝试、降级与成功一起报告。按冻结的策略重试，成功不能抹去失败。尽可能逐角色
   统计成本；供应商用量不可得时明确标注，不能按零计。
6. 运行冻结后才做错题诊断。单版本全新运行提供一次观察，不证明改进的因果效果。
   比较需要相同输入、harness 和模型设置的基线；单次随机配对仍有不确定性。

基线包括实际模型调用，不能只记展示名称。逐角色记录路由 ID、供应商、实际生效的推理
强度、输出上限、temperature、答案 schema 和回退行为，区分省略字段与显式设置。
跨版本时检查真正发出的请求：即使应用配置没有变，绑定修复也可能让此前被忽略的参数
开始生效。保留请求哈希，并在允许时保留不含认证请求头或凭据的请求正文。

说明每个对照究竟改变什么。提供全部原始材料和正本页面，与检索有限证据，是不同的
回答方法；同时改变 deliberation schema 就不是单独检验检索。替换以不同契约或模型
配置构建的知识库，改变的是编译输入产物整体，不只是框架代码。先复现基线方法，再
每次改变一个设置或明确命名的一组设置。冻结库上的回答对照不检验全新编译；全部
原文在场时答得好，也不能证明正本编译带来的增益。

记录实际落实的隔离。目录边界本身不是访问控制边界，模型也可能在训练中见过公开评测
材料。流程隔离不能证明不存在训练污染。
