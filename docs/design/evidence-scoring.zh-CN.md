# 证据评分：不确定性与来源时钟

[English](evidence-scoring.md) | **简体中文**

评分选择器判断哪些检索材料值得继续阅读。它的分数不是事实正确率、首段事实播报许可，也不是 canonical 写入许可。原有四档 rubric、归一化后的 0.5 入选线、命名候选键、分片预算和排名保底项继续作为选择策略。

## 设计决定

1. **将来源时间意图与相关性分开判断。** 可选 `SourceClockPolicy` 只把问题送入一次 TypeSafe 请求，同时询问 Noul 与 Choice。Noul 概率达到 0.8 时启用来源时钟判断，Choice confidence 达到 0.7 时采纳受支持的日历区间。模型只选区间名称；core 根据 `as_of`、Owner 时区及其历史计算 UTC 边界。支持今天/昨天、固定天数、自然周/月/年，以及完整写出的 ISO 或中文日期；事件日期不等于来源日期筛选。模糊的“最近”、小时区间、排除项与不连续区间比较仍返回未确定，不凭空补区间。

   请求有两秒上限，与检索并发；语音首查和广查共享同一个任务，结束时由 librarian 取消并回收。否定的时间意图保持原候选字符串；未配置策略时保持既有通道。已配置的策略不可用不等于否定判断：通道会暂缓提供事实并报告校验不可用，即使问题的时间意图尚未判明。这是保守的失败行为，会降低可用性，不能误说成用户需要重新提供日期。

   时间问题的精简本地日期关系紧贴对应引用时钟，并明确区分来源时间与事件时间。来源级日期、部分块时钟和未知时钟保持不同，入库时间不填补任何缺失。
2. **保留不确定性，不增加淘汰门槛。** `EvidenceScores.details` 保留每个候选可选的有序概率分布、confidence 和响应实际模型版本；请求模型和指令/rubric 的哈希另列。响应未报告版本时保持未知。confidence 表示分布集中程度，不是正确率；相同期望分数可能对应不同分布。选择继续使用原分数线。`SelectedEvidence.score_report` 为调用者保留报告，既有有界阶段预览展示聚合数据和至多八条数字样本。预览仍可能继续截断：这是诊断遥测，不是所有供应商回答的完整持久记录。
3. **拒绝异常分数。** 非有限数、布尔值及越界分数标记为未评分，不再夹到合法区间伪装成有效证据。无效可选诊断字段被省略，但不因此丢弃合法分数。缺失分布保持为空。
4. **共享并发预算。** 缓存适配器上的 semaphore 同时约束多次评分，而不是每个 recall 各开十六个槽位。这是适配器/进程级限制，不是跨进程的供应商账户限流器。取消释放槽位，连接复用和单次请求超时保留。
5. **在召回预算内尊重供应商冷却时间。** 重试识别秒数和 HTTP 日期形式的 `Retry-After`，以 250ms 指数退避为最小间隔。供应商要求等待的时间达到配置的请求超时时，该分片直接成为未评分，不无限等待，也不提前重试。默认仍只重试一次。语音外层五秒选择预算可能先于适配器六秒请求超时取消调用。

6. **在分数之外执行已采纳的来源时间区间。** 筛选前及组装/出处展开后，core 都检查完整引用块的时钟。只有全部落在区间内的 claim 与派生摘要才能保留。混合日期的逐字窗口从租户隔离的 L0 回读，拆成确切的区间内连续块；未知时钟或只有来源级日期，不能证明每个引用块都在区间内。有界来源标记阻止后续扩张越界，原始媒体也使用相同窗口检查。排名保底与评分失败兜底不能带回被排除记录；此路径关闭整页、glance 与时间线扩展。语音首查先应用同一时间范围，再进入既有首事实闸门。没有合格证据时，语音综合与普通 fast 答题都机械返回结果，不调用回答模型。策略、范围及最终数量写入有界阶段预览，空候选时也可观察。

调用方隔离候选所属租户，时间检查沿用同一边界回读 L0；不改写正本、来源或保留记录。低于评分线的材料通过时间准入后，仍可被排名保底选中。相关性、来源时间准入、引用有效性与语义忠实性各自独立：机械区间检查不能证明模型理解问题正确，也不能证明事件发生于来源写下的时刻。

## 实现前验证

先写的新测试复现了四项现状问题：异常数值进入分数、不确定性丢失、多次召回突破并发预算、忽略 `Retry-After` 提前重试。原有评分器/选择器的 27 项测试通过。另外五项测试在实现前规定新时钟行为：本地日期换算、部分覆盖、未来/来源级日期、未知日期和不可用时区。后续回归覆盖可选字段、分片对齐、取消、低 confidence 材料保留和阶段遥测。这些无密钥测试验证机制，不验证模型语义质量。

## 首轮真实模型对照，2026-09-21

首轮使用了此前无条件追加的 JSON 时钟信息。这是支持“由代码计算日期”的历史实验，不是最终输入策略；后续回放已修正全局启用的决定。

仅使用中英文合成材料，无私人知识库数据，不用模型生成标签。固定 OpenRouter 上的 `typesafe/jev-1.13-20260917`，保持四档 rubric、0.5 归一化入选线和候选分组相同。唯一实验输入变化是补入代码计算的来源时钟。预期标签不发送给 JEV。

| 样本组 | 修改前 | 修改后 |
|---|---:|---:|
| 首组：正确保留 / 错误丢弃 | 24 / 0 | 24 / 0 |
| 首组：错误保留 / 正确排除 | 14 / 46 | 0 / 60 |
| 首组：输入 token | 26,319 | 36,360 |
| 首组：单次调用中位耗时 | 323ms | 344.5ms |
| 独立组：正确保留 / 错误丢弃 | 8 / 4 | 12 / 0 |
| 独立组：错误保留 / 正确排除 | 8 / 16 | 0 / 24 |
| 独立组：输入 token | 11,658 | 15,996 |
| 独立组：单次调用中位耗时 | 331ms | 348ms |

首组有八个问题、28 个独立候选判断，重复三轮，每个版本 24 次调用；包括今天/昨天、较旧但相关的定义、事件日期不同于来源日期。独立组有十二个新问题、36 个候选判断，各版本运行一轮，交替调用次序；覆盖跨月、跨年与纽约夏令时切换。合计是 20 个问题、64 个独立判断、72 次调用，不能把重复结果算成 120 个独立测试样本。

这里测的是加入排名保底和生成答案**之前**的分数线入选行为。结果支持在这些样例上增加来源时钟信息，不代表通用检索准确率、抗注入能力或语音答案正确率。输入 token 增加约 37–38%，实测中位耗时也略增，不能称为提速。批量大小、rubric 与 confidence 阈值的变更应另做对照。

## 后续回放：真实材料候选池与按需上下文（区间准入之前）

按固定种子抽取 24 道题、4,105 个冻结候选：五道 Owner 真实提问、十道从真实 claim 生成的题、五道生成的宽泛题和四道虚构主体缺失题。保留候选正文与顺序，从 L0 只读补齐来源时钟后冻结。明确使用新的参考时刻 2026-09-21 01:00 UTC、Asia/Shanghai。这是在历史候选池上回放，不代表复现了当前线上检索或原提问的历史时刻。私人材料只放在忽略的 `local/`，本文仅保留聚合结果。

对十九道非 Owner 实际提问题，沿用既有模型评审标签：分数线入选精度/召回，原输入为 72.0%/82.1%，全局详细日期版为 69.1%/79.7%，全局精简日期版为 69.8%/81.6%；经过保底项与上限后，精度分别为 56.2%、54.0%、53.5%。这些是部分候选上的模型标签，不是人工标准答案。池内九条目标 claim 在各版均保留，第十条本来就没进池。两种全局日期版均未证明通用质量收益，所以最终不再给所有问题都加计算后的日期。

此前只用 Noul 的策略判断在 44 个探索样例及另外 24 个独立合成样例上均符合预期，包含历史事实、事件日期和名字就叫 Yesterday 的主体。在固定 0.8 阈值下，真实材料题组只启用两题：近期项目和近期工作；其余 22 题的候选字符串与原版逐字一致。这保证输入兼容，不保证随机模型每次返回相同答案。独立组策略判断中位耗时 340.5ms，24 次调用消耗 9,744 输入 token。

最终精简表示还在全部二十道冻结合成题上直接对照，64 个独立判断、交替运行前后版本：原输入的正确保留/误留/漏选/正确排除为 17/13/3/31，精简输入为 20/0/0/44。输入 token 从 20,431 增至 23,543（+15.2%），低于此前 37–38% 的增幅。这验证表示方式；另一个实验验证是否启用它，两者不能当成一轮端到端测试。

在 24 个真实材料候选池上，原版、全局详细日期版、全局精简日期版分别使用 2,665,499 / 3,476,945 / 2,972,128 输入 token，以及 161 / 250 / 195 个 HTTP 请求。把实测策略决策与各分支记录组合后，含策略判断共 2,700,447 token、187 个请求，相对原版 token 增加 1.3%。最后这个值是离线组合，不是新测的整条流水线耗时。策略判断增加一轮延迟，本文不声称整体提速。

另外，对五道真实提问使用冻结的选中证据生成答案，不重新检索，也不展开更多出处。近期工作题的候选池最新来源时刻是 9 月 17 日，问题时刻是 9 月 21 日；原版和精简版仍然把较旧的工作说成近期。因此，来源时钟输入变好不能解决候选缺失和回答边界问题。排名保底也同时补回了有用材料与噪声，没有据此取消。五次问题的回答回放不构成端到端正确性提升结论。

## 恢复后的区间准入验证，2026-09-22

使用最终 Noul+Choice 策略和同一个固定 JEV 型号，原有二十道区间题有十九道符合预期，另行编写的十二道独立样例全部符合预期；32 次请求都返回了判断。失败的是英文“今天会议记录”题：正确选择 `today`，但 Choice confidence 为 0.65，低于既有 0.7 准入线，因此返回未确定。没有针对这个结果重新调阈值。两组调用中位耗时为 306.5ms / 391ms，输入 token 为 17,980 / 10,781。这验证意图和日期解析，不验证检索完整性或回答质量。

在同一套二十道精简日期评分题上重新做对照：64 个独立候选判断，每个版本二十次调用。

| 分数线结果 | 原输入 | 精简来源时钟 |
|---|---:|---:|
| 正确保留 / 漏选 | 16 / 4 | 20 / 0 |
| 误留 / 正确排除 | 13 / 31 | 0 / 44 |
| 未评分 | 0 | 0 |
| 输入 token | 20,431 | 23,543 |
| 单次调用中位耗时 | 333ms | 364ms |

rubric、阈值、候选顺序和模型保持固定，前后版本交替执行。这个对照单独测量日期表示，不与意图策略和区间闸门混作一次端到端实验。样本很小且全为合成材料，不声称通用准确率或延迟提升。模型输出有随机性，原输入结果与此前一轮略有不同。另有无密钥整条通道测试覆盖排名兜底无法带回旧记录、混合块拆分、跨租户拒绝、校验不可用、语音共享策略取消，以及无时间准入证据时首查和最终综合都不提供事实。

## 复现

冻结的前后输入与预期标签位于 `packages/pneuma-knowledge-eval/tests/fixtures/jev-source-clocks.json`。
精简表示位于同目录的 `jev-source-clocks-compact.json`，独立策略判断样例位于 `jev-source-clock-policy.json`。
`pneuma_knowledge_eval.evidence_scoring.compare(scorer, cases, repeats=1)` 接受注入的 `EvidenceScorer`，交错重放前后版本，并单独统计未评分项。它不配置供应商、不读取凭据。两组使用同一个固定版本适配器，模型、分数线和 rubric 保持不变。上表首组为重复三轮、前后分开运行；独立组为交替次序。将来重跑是新一次测量，不保证复现相同耗时。
`evaluate_source_clock_policy(policy, cases)` 单独验证时间意图。`evaluate_source_time_scope(policy, cases, as_of=..., zone=...)` 进一步验证日历区间，对应 `source-time-window-cases.json` 与独立的 `source-time-window-holdout.json`。预期日期和标签留在 eval 叶子包，策略只接收问题；不可用结果单列为未评分，不算正确否定。

## 官方依据

- [Jev 1.13 jaggedness](https://docs.typesafe.ai/model-jaggedness/jev-1.13)：算术和日期比较交给代码，减少无关 state 与间接引用。
- [Score](https://docs.typesafe.ai/primitives/score) 与 [Confidence](https://docs.typesafe.ai/confidence)：区分概率分布、期望分数与事实正确性。
- [API](https://docs.typesafe.ai/api)：可重试故障与退避。TypeSafe 原生端点的限制、模型别名不会自动成为本项目 OpenRouter 路由的合同。
